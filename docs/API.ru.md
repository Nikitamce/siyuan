## Спецификация

### Параметры и возвращаемые значения

* Конечная точка (endpoint): `http://127.0.0.1:6806`
* Если в описании интерфейса не указано иное, все API-интерфейсы используют метод POST
* Для интерфейсов, принимающих JSON-параметры, параметры передаются в виде JSON-строки в теле запроса (`body`), заголовок `Content-Type` должен быть `application/json`
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {}
  }
  ```

    * `code`: значение, отличное от 0, означает ошибку/исключение
    * `msg`: в нормальном состоянии — пустая строка; в случае ошибки возвращается текст сообщения об ошибке
    * `data`: может быть `{}`, `[]` или `NULL` в зависимости от конкретного интерфейса

### Контракты типов TypeScript

Объявления `fetchPost`, `fetchSyncPost` и `fetchGet` в плагинах выводят типы запросов и ответов из контрактов, сгенерированных ядром, для перенесённых путей интерфейсов. Охват постоянно расширяется и включает базовые системные интерфейсы, пакетное чтение/запись атрибутов блоков, операции с тегами и закладками, часть запросов блоков, список блокнотов, поиск по истории и операции со снимками (snapshots). Существующие неперенесённые интерфейсы и динамические URL продолжают поддерживаться. Перед чтением данных успешного ответа из асинхронного возвращаемого значения необходимо проверить код ответа и явно обработать nullable-поля.

```typescript
import {fetchSyncPost} from "siyuan";

const response = await fetchSyncPost("/api/attr/getBlockAttrs", {id: blockID});
if (response.code === 0 && response.data) {
    const value = response.data["custom-value"];
}
```

Точный охват см. в [сгенерированных объявлениях маршрутов](../app/src/types/api/index.d.ts), а правила генерации и совместимости — в [описании сопровождения контрактов](API-CONTRACTS.md). Сами объявления типов не выполняют проверку JSON во время выполнения.

### Семантика поведения

* К публичному API относятся только интерфейсы, для которых в данном документе приведено отдельное описание. Прочие маршруты ядра и операции `/api/transactions` являются внутренней реализацией; если не указано иное, их совместимость и стабильность поведения не гарантируются
* `code: 0` означает, что при обработке запроса интерфейсом не возникло ошибок, и гарантирует только результат, явно описанный для этого интерфейса, но не означает, что связанные индексы, кэши, WebSocket-трансляции или состояние синхронизации уже обновлены
* Значение пропущенных полей, `null`, пустых объектов и пустых массивов определяется каждым интерфейсом отдельно. Заменяют ли объекты или массивы текущее состояние, объединяются с ним или изменяют его частично, а также имеет ли значение порядок элементов, также определяется описанием конкретного интерфейса
* Интерфейс может обрезать, игнорировать, заполнять или преобразовывать входные данные. Если в описании интерфейса указано, что возвращается нормализованный результат, вызывающая сторона должна использовать возвращённое поле `data` как фактически принятый результат
* Не следует делать вывод о том, что операция является операцией только для чтения, исходя из её названия. При наличии побочных эффектов сохранения каждый интерфейс описывает область их влияния
* Идемпотентность или безопасность повторных попыток для одинаковых запросов гарантируется только в том случае, если это явно указано в описании интерфейса. При прерывании ответа или неопределённости результата следует по возможности сначала прочитать текущее состояние, прежде чем принимать решение о повторном запросе

### Переименовать блокнот

`name` — это отображаемое имя в виде обычного текста, оно сохраняет полуширинный символ `/` и различает его с полноширинным `／`, не создавая при этом каталог; идентификатор блокнота по-прежнему определяется его ID.

При наличии документа блокнота переименование синхронизирует его заголовок в виде обычного текста. Для форматированного (rich-text) заголовка передача текущего имени блокнота без изменений оставляет его как есть, а другие имена будут отклонены для сохранения стилей, изображений и ссылок. Для редактирования полного заголовка необходимо вызвать `getDocTitle` с ID блокнота, а затем отправить транзакцию `setDocTitle` с `expectedRevision`.

* `/api/notebook/renameNotebook`

  ```json
    "notebook": "20210831090520-7dvbdv0",
    "name": "Новое имя блокнота"
  }
  ```

* Возвращаемое значение

  ```json
  {
    "code": 0,
  ```


### Получить конфигурацию блокнота

Ответ для администратора также может содержать доступный только для чтения объект `documentCapabilities`, сообщающий о поддержке структурированных интерфейсов, форматах заголовков, состоянии индекса и сводке возможностей. Все блокноты используют правила структурированных заголовков, не требуя настройки режима или миграции; `literalSlash` принимает значение `true` только тогда, когда индекс готов. Совместимость зависит от исходной спецификации и представления заголовка каждого документа. Синхронизация передаёт документы как необработанные байты, не интерпретируя неподдерживаемые исходные форматы. Для чтения, индексации и редактирования по-прежнему требуется версия, поддерживающая этот формат; восстановление снимков сохраняет предварительную проверку исходной спецификации. Существующая фильтрация прав доступа остаётся неизменной.

* `/api/notebook/getNotebookConf`
* Параметры

  ```json
  {
    "notebook": "20210817205410-2kvfpfn"
  }
  ```

    * `notebook`: ID блокнота
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "box": "20210817205410-2kvfpfn",
      "conf": {
        "name": "Тестовый блокнот",
        "closed": false,
        "refCreateSavePath": "",
        "createDocNameTemplate": "",
        "dailyNoteSavePath": "/daily note/{{now | date \"2006/01\"}}/{{now | date \"2006-01-02\"}}",
        "dailyNoteTemplatePath": ""
      },
      "name": "Тестовый блокнот"
    }
  }
  ```

Ответ для администратора также содержит необязательный объект только для чтения `documentCapabilities`. `structuredPaths` указывает, что серверная часть поддерживает интерфейсы ID и сегментов пути, но не предоставляет прав доступа к закрытым или заблокированным блокнотам. `titleFormats` перечисляет поддерживаемые форматы заголовков, `indexState` сообщает о состоянии индекса, а `revision` идентифицирует объявление возможностей. `literalSlash` принимает значение `true` только при готовности индекса. Совместимость зависит от исходной спецификации и представления заголовка каждого документа. Синхронизация передаёт документы в виде необработанных байтов без интерпретации неподдерживаемых исходных форматов. Для чтения, индексации и редактирования по-прежнему требуется версия, поддерживающая данный формат; восстановление из снимка сохраняет предварительную проверку исходной спецификации. Отсутствие этого объекта на старом сервере отличается по смыслу от сбоя запроса — нельзя откатываться к старым интерфейсам путей для продолжения записи после сбоя запроса.

  ```json
        "dailyNoteTemplatePath": ""
      }
  }
  ```

    * `notebook`: ID блокнота
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "name": "Тестовый блокнот",

      "refCreateSavePath": "",
      "createDocNameTemplate": "",
      "dailyNoteSavePath": "/daily note/{{now | date \"2006/01\"}}/{{now | date \"2006-01-02\"}}",

    }
  }
  ```

## Документы

### Создать документ из Markdown

Старый строковый интерфейс создания проверяет все префиксы родительского пути перед записью. Если предок содержит косую черту или пустой заголовок, возвращается `code: -1`, `data.reason: "pathAmbiguous"`; при наличии нескольких чистых родительских элементов требуется действительный и совпадающий `parentID`, иначе также сообщается о неоднозначности. Если метаданные не готовы, возвращается `indexUnavailable`. Рекомендуется использовать [Создать документ по ID родительского документа](#создать-документ-по-id-родительского-документа), передавая отдельно идентификатор родителя и заголовок.

* `/api/filetree/createDocWithMd`
* Параметры

  ```json
  {
    "notebook": "20210817205410-2kvfpfn",
    "path": "/foo/bar",
    "markdown": ""
  }
  ```

    * `notebook`: ID блокнота
    * `path`: путь к документу, должен начинаться с `/` и использовать `/` для разделения уровней (соответствует полю `hpath` в базе данных)
        * `/` является разделителем уровней и не может представлять косую черту в заголовке документа; несуществующие родительские документы создаются автоматически
        * Например, `/Notes/Programming in C/C++` создаст документ с заголовком `C++` внутри `Programming in C` под `Notes`
        * Программы импорта должны обрабатывать заголовки по одному перед объединением пути, например заменяя ASCII `/` на полноширинную `／` (U+FF0F): `/Notes/Programming in C／C++` создаст документ с заголовком `Programming in C／C++` под `Notes`. Такая замена изменяет текст заголовка
    * `markdown`: содержимое GFM Markdown
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": "20210914223645-oj2vnx2"
  }
  ```

    * `data`: ID созданного документа
    * Повторный вызов этого интерфейса с тем же `path` не перезапишет существующий документ

### Создать документ по ID родительского документа

Создаёт документ под существующим родительским документом. Требуются права администратора, доступная для записи рабочая область, а также открытый блокнот с готовыми метаданными документов; зашифрованный блокнот должен быть разблокирован.

* `/api/filetree/createDocByParent`
* Параметры

  ```json
  {
    "notebook": "20210817205410-2kvfpfn",
    "parentID": null,
    "id": "20261030150000-abc1234",
    "title": {
      "format": "plain",
      "text": "C/C++"
    },
    "markdown": "Hello"
  }
  ```

    * `notebook`: ID целевого блокнота
    * `parentID`: ID существующего родительского документа в этом блокноте; для корневого уровня передайте `null`; обязательно, нельзя передавать пустую строку
    * `id`: ID нового документа, сгенерированный и сохранённый перед отправкой; фронтенд SiYuan может использовать `Lute.NewNodeID()`; для каждого нового документа необходимо заменять пример ID
    * `title`: объект заголовка, `format` должен быть `plain`, `text` обязателен; разметка Markdown обрабатывается как буквальный текст, `/` сохраняется в заголовке
    * `title.text`: максимум 512 кодовых точек Unicode; пустой текст создаст маркер пустого заголовка и отобразит текст-заполнитель; начальные/конечные пробелы, недопустимые символы, `.` и `..` будут отклонены
    * `markdown`: содержимое основного текста в формате GFM, может быть пустой строкой
    * `expectedParentRevision`: версия родительского документа, возвращённая запросом пути, необязательно; для корневого уровня используйте `data.start.revision` из `resolveDocPath`; при несовпадении возвращается `planChanged`
    * `nameConditions`: максимум 128 объектов `{parentID, title, expectedID}`, необязательно; все три поля каждого объекта обязательны; `parentID: null` означает корневой уровень; `expectedID: null` требует отсутствия дочернего документа с таким же именем, иначе требуется ровно один одноимённый дочерний документ с совпадающим ID; область действия условий — целевой родитель и его предки
    * `expectedTarget`: `{notebook, purpose, revision}` из плана создания, сгенерированного по конфигурации, необязательно; `purpose` может быть `document`, `reference` или `dailyNote`; при изменении конфигурации возвращается `planChanged`
    * `tags`: теги документа через запятую, необязательно, по умолчанию пустая строка, ограничено возможностями блокнота
    * `withMath`: включить ли разбор строчных формул, необязательно, по умолчанию `false`
    * `clippingHref`: URL-адрес источника веб-клиппинга, необязательно, по умолчанию пустая строка; адреса статей сообщества включают соответствующие параметры синтаксиса Markdown
    * `sorts`: массив путей хранения соседних документов в пользовательском порядке, необязательно, по умолчанию `[]`; нельзя использовать одновременно с `sortTargetID`
    * `sortTargetID`: ID целевого соседнего документа для относительной сортировки, необязательно, должен передаваться вместе с `sortPosition`
    * `sortPosition`: `before` или `after`, необязательно, должен передаваться вместе с `sortTargetID`; если параметры сортировки не указаны, используется настройка сортировки новых документов блокнота
    * `docCreateTemplatePath`: путь к шаблону основного текста, необязательно, по умолчанию пустая строка, применяется только когда `markdown` пуст
    * `listDocTree`: флаг обновления дерева документов в уведомлении о создании, необязательно, по умолчанию `false`
    * Только `parentID` принимает `null`; неизвестные поля, такие как `path`, `hPath` и др., будут отклонены
    * Отсутствующие родительские документы не создаются автоматически; если ID родителя недействителен, указывает на блок основного текста или принадлежит другому блокноту, возвращается ошибка
    * Существующий ID возвращает `documentIDConflict`; при отсутствии ограничений по условиям имени разные ID могут создавать документы с одинаковыми именами
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "id": "20261030150000-abc1234",
      "document": {
        "notebook": "20210817205410-2kvfpfn",
        "id": "20261030150000-abc1234",
        "parentID": null,
        "path": "/20261030150000-abc1234.sy",
        "title": {
          "format": "plain",
          "text": "C/C++",
          "empty": false
        },
        "segments": [
          {
            "id": "20261030150000-abc1234",
            "text": "C/C++",
            "empty": false
          }
        ],
        "depth": 1,
        "displayPath": "/C/C++",
        "revision": "opaque-revision"
      }
    }
  }
  ```

    * `data.id`: ID созданного документа
    * `data.document`: метаданные документа; эту же структуру используют интерфейсы запроса пути далее
    * `data.document.parentID`: ID родительского документа, для корневого уровня `null`
    * `data.document.path`: путь хранения `.sy` на основе ID
    * `data.document.title`: сводка заголовка, `format` — `plain` или `inline-ast`, `text` — отображаемый текст, `empty` означает явный пустой заголовок
    * `data.document.segments`: цепочка предков, включающая текущий документ; каждый сегмент содержит `id`, `text`, `empty`
    * `data.document.depth`: количество сегментов пути
    * `data.document.displayPath`: отображаемый путь; заголовок может содержать `/`, поэтому его нельзя разбивать для обратного восстановления ID документа
    * `data.document.revision`: строка версии для последующей проверки; при вызове необходимо заменить `opaque-revision` из примера на фактическое возвращённое значение

Пример параметров для создания дочернего документа под указанным выше документом:

```json
{
  "notebook": "20210817205410-2kvfpfn",
  "parentID": "20261030150000-abc1234",
  "id": "20261030150001-def5678",
  "title": {
    "format": "plain",
    "text": "Child"
  },
  "markdown": "Child content",
  "expectedParentRevision": "opaque-revision",
  "nameConditions": [
    {
      "parentID": "20261030150000-abc1234",
      "title": "Child",
      "expectedID": null
    }
  ]
}
```

`expectedParentRevision` использует возвращённую версию родительского документа. Условие имени требует, чтобы `Child` ещё не существовал. О создании недостающих многоуровневых родительских документов см. [Разрешить путь документа по сегментам заголовка](#разрешить-путь-документа-по-сегментам-заголовка).

* При ошибке создания возвращается `code: -1`, а при наличии информации о сбойном шаге возвращается следующий объект `data`

  ```json
  {
    "code": -1,
    "msg": "parent document changed after planning",
    "data": {
      "reason": "planChanged",
      "commitState": "none",
      "stage": "source",
      "completed": []
    }
  }
  ```

    * `data.reason`: причина ошибки
        * `invalidTitle`: недопустимый заголовок
        * `unsupportedTitleFormat`: формат создания не является `plain`
        * `parentUnavailable`: родительский документ недоступен
        * `planChanged`: изменилась версия родителя, условия имени, целевая конфигурация или цель сортировки
        * `documentIDConflict`: ID уже занят
        * `indexUnavailable`: метаданные не готовы или несогласованны
        * `writeFailed`: прочие ошибки создания, сортировки или шаблона
    * `data.commitState`: `none` означает, что документ не был сохранён этим вызовом; `committed` означает, что документ сохранён, но последующие шаги могли завершиться ошибкой; `unknown` означает, что невозможно определить, был ли документ сохранён
    * `data.id`: ID документа, сохранение которого подтверждено, необязательно
    * `data.stage`: этап, на котором произошёл сбой, например `validate`, `source`, `sort`, `template`
    * `data.completed`: завершённые этапы, например `source`, `sort`
    * Ошибки разбора запроса, аутентификации и доступа к блокноту могут возвращать только обычную структуру ошибки

При сбое сортировки или шаблона уже сохранённый документ сохраняется. При тайм-ауте, потере ответа или результате `unknown` дождитесь готовности метаданных, [запросите исходный ID](#получить-пути-документов-по-ids), проверьте родителя, заголовок, основной текст и незавершённые шаги, а затем решите, как повторить попытку. Совпадение только ID не доказывает успешность всех шагов; следует сохранить исходный ID, избегать автоматического повторного применения шаблона и не откатываться к старым интерфейсам путей для записи.

### Разрешить путь документа по сегментам заголовка

Пошагово разрешает заголовки начиная с указанной позиции, не создавая документы. Требуются права администратора, а также открытый, разблокированный блокнот с готовыми метаданными документов.

* `/api/filetree/resolveDocPath`
* Параметры

  ```json
  {
    "notebook": "20210817205410-2kvfpfn",
    "start": {
      "kind": "root"
    },
    "segments": [
      "Notes",
      "C/C++"
    ]
  }
  ```

    * `notebook`: ID блокнота
    * `start`: для корневой позиции используйте `{kind: "root"}` без `id`, для существующего документа — `{kind: "document", id: "existing-document-id"}`; ID корневого документа блокнота считается логической корневой позицией
    * `segments`: массив из 0–128 непустых заголовков, сопоставляемых точно по уровням; `/` внутри заголовка является буквальным символом и не подвергается нормализации Unicode, преобразованию ширины символов или процентному декодированию
    * Документ с пустым заголовком должен задаваться в качестве начальной точки через ID документа; при пустом массиве сегментов возвращается начальный документ или корневая позиция
* Возвращаемое значение

  В следующем примере возвращаемого значения предполагается, что `Notes` не существует.

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "status": "missing",
      "start": {
        "notebook": "20210817205410-2kvfpfn",
        "id": null,
        "revision": "opaque-root-revision"
      },
      "resolved": null,
      "nextIndex": 0,
      "candidates": [],
      "candidatesTruncated": false,
      "nameConditions": [
        {
          "parentID": null,
          "title": "Notes",
          "expectedID": null
        }
      ]
    }
  }
  ```

    * `data.status`: `resolved` (разрешено), `missing` (отсутствует) или `ambiguous` (неоднозначно); во всех трёх случаях возвращается `code: 0`
    * `data.start`: начальный блокнот, ID документа (`null` для корневой позиции) и версия
    * `data.resolved`: последний однозначно разрешённый документ, структура аналогична метаданным документа выше; для корневой позиции `null`
    * `data.nextIndex`: индекс с нуля для отсутствующего или неоднозначного сегмента; при полном успешном разрешении равен `segments.length`
    * `data.candidates`: одноимённые кандидаты для неоднозначного сегмента, отсортированные по ID, максимум 128 элементов; необходимо явно выбрать ID документа
    * `data.candidatesTruncated`: имеются ли ещё кандидаты
    * `data.nameConditions`: однозначные совпадения и первое отсутствующее имя; передача обратно при создании позволяет проверить изменения, произошедшие после запроса
    * При ошибке возвращается `code: -1`, может содержать `data.reason`; ошибка не означает отсутствие документа

При импорте `/Notes/2026-10-30/Article` сегменты родительских заголовков — `["Notes", "2026-10-30"]`, а конечный заголовок — `"Article"`:

1. Разрешите сегменты родительских заголовков от корневой позиции; при `ambiguous` явно выберите родительский документ по ID
2. При `missing` создайте `segments[nextIndex]` с `markdown: ""`; в качестве `parentID` используйте `resolved.id`, а если `resolved` равно `null` — `start.id`; передайте соответствующую версию как `expectedParentRevision`, верните `nameConditions` и сохраните назначенный ID документа
3. После успеха повторно разрешите сегменты родительских заголовков и повторяйте досоздание, пока все уровни не будут успешно разрешены; после каждого создания обновляйте условия имени
4. Под разрешённым родительским документом создайте `Article`, передав версию родителя и итоговый текст Markdown; если требуется уникальность конечного заголовка, добавьте `{parentID, title: "Article", expectedID: null}` при общем количестве условий не более 128

Каждый документ сохраняется отдельно. При последующем сбое уже созданные родительские документы сохраняются; перед продолжением проверьте результат сбойного шага. Весь путь не фиксируется и не откатывается как единая операция.

### Получить пути документов по IDs

Читает метаданные документов по ID. Требуются права администратора, а также открытый, разблокированный блокнот с готовыми метаданными документов.

* `/api/filetree/getDocPaths`
* Параметры

  ```json
  {
    "notebook": "20210817205410-2kvfpfn",
    "ids": [
      "20261030150000-abc1234",
      "20261030150001-def5678"
    ]
  }
  ```

    * `notebook`: ID блокнота
    * `ids`: от 1 до 128 действительных ID документов, дедуплицируются в порядке первого появления
    * `includeIcons`: необязательное логическое значение, по умолчанию `false`; при `true` считывает иконки возвращаемых документов и их предков
* Возвращаемое значение

    * `data.documents`: массив метаданных документов, возвращаемых в порядке запроса; структуру см. в [результате создания](#создать-документ-по-id-родительского-документа)
    * `data.missingIDs`: ID, которые не существуют, принадлежат другому блокноту или указывают на блок основного текста
    * `data.icons`: необязательное отображение, где ключ — ID документа или предка, а значение — исходная сохранённая иконка (или пустая строка, если не задана). Возвращается только когда `includeIcons` равно `true`; иконка не влияет на значение ревизии пути. При ошибке чтения исходного файла возвращается ошибка, а отсутствующие документы не досоздаются
    * Любой из массивов может быть пустым; если метаданные не готовы или несогласованны, возвращается ошибка, а не результат отсутствия
    * Чтение отдельного документа согласовано, однако пакетный запрос не гарантирует единый снимок

Этот интерфейс не возвращает основной текст. При проверке неопределённого результата создания сначала найдите документ по исходному ID, затем отдельно прочитайте основной текст и проверьте оставшиеся шаги сортировки, шаблона или импорта.

### Переименовать документ

Следующие два интерфейса переименования принимают обычный заголовок. Для форматированного заголовка передача текущей текстовой сводки без изменений не вносит правок, а передача другой сводки отклоняет запись для защиты полного исходного содержимого. Для редактирования форматированного заголовка следует использовать транзакцию источника заголовка, объявленную в сгенерированном контракте API.

* `/api/filetree/renameDoc`
* Параметры

  ```json
  {
    "notebook": "20210831090520-7dvbdv0",
    "path": "/20210902210113-0avi12f.sy",
    "title": "Новый заголовок документа"
  }
  ```

    * `notebook`: ID блокнота
    * `path`: путь к документу
    * `title`: новый заголовок
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

Переименование документа по `id`:

* `/api/filetree/renameDocByID`
* Параметры

  ```json
  {
    "id": "20210902210113-0avi12f",
    "title": "Новый заголовок документа"
  }
  ```

    * `id`: ID документа
    * `title`: новый заголовок
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

### Удалить документ

* `/api/filetree/removeDoc`
* Параметры

  ```json
  {
    "notebook": "20210831090520-7dvbdv0",
    "path": "/20210902210113-0avi12f.sy"
  }
  ```

    * `notebook`: ID блокнота
    * `path`: путь к документу
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

Удаление документа по `id`:

* `/api/filetree/removeDocByID`
* Параметры

### Установить способ сортировки дочерних документов

* `/api/filetree/setDocSortMode`
* Параметры

  ```json
  {
    "id": "20210917220056-yxtyl7i",
    "sortMode": 4
  }
  ```

    * `id`: ID обычного документа, для которого задаётся способ сортировки дочерних документов; ID корневого документа блокнота не принимается
    * `sortMode`: целое число от `0` до `14`; передача `null` очищает явную настройку этого документа и последовательно наследует правило сортировки ближайшего родительского документа, блокнота или глобального дерева документов
    * Значения: `0`/`1` имя файла по возрастанию/убыванию; `2`/`3` время обновления по возрастанию/убыванию; `4`/`5` имя файла с естественной сортировкой чисел по возрастанию/убыванию; `6` пользовательская сортировка; `7`/`8` количество ссылок по возрастанию/убыванию; `9`/`10` время создания по возрастанию/убыванию; `11`/`12` размер по возрастанию/убыванию; `13`/`14` количество дочерних документов по возрастанию/убыванию
    * Заданный способ сортировки наследуется более глубокими потомками, пока другой документ не задаст собственный способ сортировки
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
  ```

## Ресурсные файлы

### Загрузить ресурсный файл
* `/api/asset/upload`
* Параметры передаются в виде HTTP Multipart-формы

    * `assetsDirPath`: путь к папке для сохранения ресурсных файлов, с папкой `data` в качестве корневой, например:
        * `"/assets/"`: папка `рабочая_область/data/assets/`
        * `"/assets/sub/"`: папка `рабочая_область/data/assets/sub/`

      В обычных случаях рекомендуется использовать первый вариант и сохранять всё в общей папке ресурсов рабочей области, так как запись в подкаталоги имеет ряд побочных эффектов — подробнее см. в разделе о ресурсных файлах руководства пользователя.
    * `file[]`: список загружаемых файлов
    * `excludeFromCleanup`: необязательный текст формы, принимает только `"true"` или `"false"`, при пропуске считается `false`. При значении `true` успешно загруженные или повторно использованные обычные ресурсы добавляются в правила исключения из очистки; файлы, для которых не удалось сохранить правило, не возвращаются как успешные. Эта опция не поддерживается для ресурсов зашифрованных блокнотов
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "disk full",
    "data": {
      "errFiles": ["bar.png"],
      "failedFiles": [
        {
          "index": 1,
          "name": "bar.png",
          "error": "disk full"
        }
      ],
      "succFiles": [
        {
          "index": 0,
          "name": "foo.png",
          "path": "assets/foo-20210719092549-9j5y79r.png"
        }
      ],
      "succMap": {
        "foo.png": "assets/foo-20210719092549-9j5y79r.png"
      }
    }
  }
  ```

    * `errFiles`: имена файлов, при обработке которых возникли ошибки
    * `failedFiles`: запись файлов, для которых явно сообщено о сбое; `index` — индекс файла в `file[]`, `name` — имя файла при загрузке, `error` — сообщение об ошибке; это поле может не включать файлы, которые не обрабатывались или не были отражены поштучно; для однозначного подтверждения каждого входного элемента следует использовать `succFiles`
    * `succFiles`: запись успешно обработанных файлов в порядке ввода; `index` — индекс файла в `file[]`, `name` — имя файла при загрузке, `path` — путь к ресурсному файлу после загрузки; следует использовать это поле, если одна партия содержит файлы с одинаковыми именами
    * `succMap`: отображение успешных файлов, сохранённое для совместимости с существующими вызывающими сторонами; ключ — имя файла при загрузке, значение — `assets/foo-id.png`; при наличии одноимённых файлов в одной партии сохраняется только последний элемент для данного ключа

## Блоки

При вставке, вставке в начало, добавлении в конец и обновлении блоков перед сохранением проверяются ID всех блоков в отправляемом поддереве. Отсутствующие ID генерируются системой; явно указанные ID должны соответствовать формату `YYYYMMDDhhmmss-xxxxxxx` (семь строчных букв или цифр после дефиса), быть уникальными во входных данных и не конфликтовать с существующими блоками. При обновлении можно сохранять ID из заменяемого поддерева. Недопустимая запись возвращает ошибку, а изменение не сохраняется.

### Вставить блок

* `/api/block/insertBlock`
* Параметры

  ```json
  {
    "dataType": "markdown",
    "data": "foo**bar**{: style=\"color: var(--b3-font-color8);\"}baz",
    "nextID": "",
    "previousID": "20211229114650-vrek5x6",
    "parentID": ""
  }
  ```

    * `dataType`: тип вставляемых данных, может быть `markdown` или `dom`
    * `data`: вставляемые данные
    * `nextID`: ID следующего блока для привязки позиции вставки
    * `previousID`: ID предыдущего блока для привязки позиции вставки
    * `parentID`: ID родительского блока для привязки позиции вставки

  Хотя бы один из трёх параметров `nextID`, `previousID`, `parentID` должен иметь значение; приоритет: `nextID` > `previousID` > `parentID`
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": [
      {
        "doOperations": [
          {
            "action": "insert",
            "data": "<div data-node-id=\"20211230115020-g02dfx0\" data-node-index=\"1\" data-type=\"NodeParagraph\" class=\"p\"><div contenteditable=\"true\" spellcheck=\"false\">foo<strong style=\"color: var(--b3-font-color8);\">bar</strong>baz</div><div class=\"protyle-attr\" contenteditable=\"false\"></div></div>",
            "id": "20211230115020-g02dfx0",
            "parentID": "",
            "previousID": "20211229114650-vrek5x6",
            "retData": null
          }
        ],
        "undoOperations": null
      }
    ]
  }
  ```

    * `action.data`: DOM, сгенерированный для нового вставленного блока
    * `action.id`: ID первого вставленного блока верхнего уровня; если за один раз вставляется несколько блоков верхнего уровня и нужно получить ID каждого из них, вставляйте по одному блоку за запрос

## SQL

### Выполнить SQL-запрос

* `/api/query/sql`
* Параметры

  ```json
  {
    "stmt": "SELECT * FROM blocks WHERE content LIKE'%content%' LIMIT 7"
  }
  ```

    * `stmt`: SQL-скрипт
    * `mode`: необязательный режим; пропуск, `null` или `""` разрешают один запрос чтения/записи; `"readonly"` разрешает только один запрос `SELECT` или `WITH` только для чтения; `"multiple"` последовательно выполняет несколько операторов и возвращает результат последнего

Операторы без столбцов результата (включая `INSERT`, `UPDATE`, `DELETE` и DDL) также выполняются и при успехе возвращают `data: []`; `RETURNING` сохраняет строки результата. Ошибка валидации возвращает `code: -1`, ошибка выполнения — `code: 1`. Выполнение нескольких операторов останавливается на первом сбое, при этом уже выполненные записи не откатываются автоматически. Прямая запись через SQL воздействует на производную индексную базу данных, не обновляет исходные документы и не поддерживает полнотекстовый индекс и кэш блоков; для редактирования содержимого документов используйте интерфейсы блоков.

Если внешний `LIMIT` не указан явно, по умолчанию возвращается максимум `search.limit` строк (количество результатов поиска в настройках). Поэтому используйте явные `LIMIT` и `OFFSET` для пагинации, а также стабильную и уникальную сортировку, например `ORDER BY hpath, id`. Явный внешний `LIMIT` переопределяет ограничение по умолчанию и может превышать `search.limit`.

* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": [
      { "столбец": "значение" }
    ],
    "limit": 0,
    "truncated": false
  }
  ```

При успехе `data` остаётся массивом. `limit` означает применённый сервером лимит по умолчанию для этого запроса; если в SQL явно указан внешний `LIMIT`, значение равно `0` (оно не отражает число, указанное в этом предложении). `truncated` равно `true` только тогда, когда из-за серверного лимита по умолчанию не была возвращена хотя бы одна строка результата; точное достижение лимита усечением не считается. В примере выше явно указан `LIMIT 7`, поэтому `limit` равен `0`, а `truncated` — `false`. Ответы об ошибках не содержат этих двух полей.

Примечание: в целях безопасности данных доступ к этому интерфейсу запрещён в режиме публикации.

### Отправить транзакцию

* `/api/sqlite/flushTransaction`
* Без параметров
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

Интерфейсы записи блоков могут возвращать ответ, когда транзакция дерева блоков уже зафиксирована, а асинхронная индексация SQL ещё не завершена. Если требуется немедленно прочитать эту запись через `/api/query/sql`, вызовите `POST /api/sqlite/flushTransaction` после записи, дождитесь ответа `code: 0` и только затем выполняйте SQL-запрос. Например, `getBlockKramdown` читает дерево блоков и может отобразить недавно записанное содержимое раньше, чем индекс SQL. Kramdown, DOM и столбцы SQL — это разные представления содержимого, и ни одно из них не является нормализованным обычным текстом.

## Шаблоны

### Рендеринг шаблона

* `/api/template/render`

При отсутствии интерактивного онлайн-окна `httpGet` возвращает `interaction_required` и не отправляет сетевые запросы. «Разрешить в этот раз» даёт текущей выполняемой версии того же шаблона доступ к нескольким публичным сетевым целям, включая последующие запросы и перенаправления, позволяя отправлять внешним сервисам содержимое заметок, к которому у неё есть доступ на чтение, но не расширяя права на чтение. Постоянное разрешение действует только для распознанных ядром файлов или источников шаблонов полей базы данных и их версий содержимого, применяется локально в текущей рабочей области, не ограничивается текущим целевым документом или разблокированным блокнотом, не передаётся при встроенном экспорте или синхронизации и может быть отозвано в управлении шаблонами или настройках поля базы данных. Подключаемые дочерние файлы шаблонов не наследуют разрешение родительского шаблона; после изменения, копирования или импорта требуется повторное подтверждение. Фоновое выполнение, опубликованные страницы или заблокированные блокноты не могут использовать эти разрешения для обхода интерактивных проверок или проверок доступа.
* Параметры

  ```json
  {
    "id": "20220724223548-j6g0o87",
    "path": "F:\\SiYuan\\data\\templates\\foo.md",
    "mode": "editorInsert"
  }
  ```

    * `id`: ID документа, в котором вызывается рендеринг
    * `path`: абсолютный путь к файлу шаблона
    * `mode`: необязательный режим рендеринга. В настоящее время поддерживаются только `"preview"` и `"editorInsert"`. Режим предпросмотра генерирует план дерева документов без записи файлов; режим вставки в редактор генерирует план, который после подтверждения может быть применён через соответствующую транзакцию редактора
    * `httpConfirmToken`: необязательный токен подтверждения, возвращаемый успешным предпросмотром без необходимости выбора «Всегда разрешать». При отправке с `mode: "editorInsert"` в течение 30 секунд он может использоваться для одной вставки в том же окне при условии, что исходный код шаблона и его зависимости, целевой документ и блокнот, а также фактический запрос не изменились. Повторно используется только подтверждение, а при вставке данные запрашиваются заново. При изменении контекста, отзыве, истечении срока действия или использовании токена происходит возврат к обычной проверке разрешений шаблона. Закрытие или переключение предпросмотра, блокировка блокнота или разрыв соединения делают передачу недействительной; `/api/template/cancelHTTP` также принимает необязательный `httpConfirmToken` для отмены передачи. Эта передача не применяется к выполнению в базе данных или ежедневных заметках
    * При пропуске `mode` по-прежнему поддерживается старый логический параметр `preview`: `preview: true` эквивалентно `mode: "preview"`; в противном случае шаблон рендерится как обычное содержимое, а `createDocTree` отключается
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "content": "<div data-node-id=\"20220729234848-dlgsah7\" data-node-index=\"1\" data-type=\"NodeParagraph\" class=\"p\" updated=\"20220729234840\"><div contenteditable=\"true\" spellcheck=\"false\">foo</div><div class=\"protyle-attr\" contenteditable=\"false\">​</div></div>",
      "path": "F:\\SiYuan\\data\\templates\\foo.md",
      "docTreePlan": {
        "id": "template-plan-token",
        "count": 2,
        "nodes": [
          {
            "id": "20260830150000-abc1234",
            "title": "Materials",
            "parentID": "20220724223548-j6g0o87",
            "hPath": "/Parent/Materials",
            "depth": 1
          },
          {
            "id": "20260830150001-def5678",
            "title": "Review",
            "parentID": "20260830150000-abc1234",
            "hPath": "/Parent/Materials/Review",
            "depth": 2
          }
        ]
      }
    }
  }
  ```

    * `httpConfirmToken`: необязательный одноразовый токен подтверждения, выдаваемый после успешного интерактивного предпросмотра; область применения и 30-секундный срок действия описаны в полях запроса
    * `docTreePlan`: возвращается, когда шаблон объявляет дерево дочерних документов через `createDocTree`
        * `id`: пусто в режиме предпросмотра, файлы не записываются. В режиме вставки в редактор — краткосрочный одноразовый токен плана; после подтверждения передайте его как поле верхнего уровня `templateDocTreePlanID` соответствующего объекта транзакции
        * `count`: общее количество дочерних документов в плане
        * `nodes`: статическое описание запланированных документов
            * `id`: ID запланированного документа
            * `title`: заголовок запланированного документа
            * `parentID`: ID запланированного родительского документа
            * `hPath`: человекочитаемый путь запланированного документа
            * `depth`: глубина относительно документа, в который вставляется шаблон
        * Один план может содержать максимум 128 документов, а объявленное дерево дочерних документов — максимум 16 уровней. Абсолютная глубина итогового дерева файлов по-прежнему ограничена настройкой разрешения на создание дочерних документов глубже 7 уровней

### Записать файл

* `/api/file/putFile`

При записи по пути документа `.sy`, состоящему из ID блокнота и ID документа, одновременно проверяются переданное содержимое и существующий документ. Неизвестный формат, повреждённый источник документа или заголовок, содержащий `/` без объявления требуемого Spec 6, возвращают `code: -1`, сохраняя исходный файл и время изменения; успешная запись сохраняет необработанные байты из запроса без нормализации заголовка. Файлы `.sy` в каталогах вложений или плагинов не разбираются как документы.

Если новый переданный заголовок содержит ASCII `/`, должен быть объявлен `Spec` не ниже `6`, иначе возвращается `code: -1`, `msg: "document title requires spec 6"` без автоматического переписывания содержимого. Существующие источники с низким Spec по-прежнему можно читать, а также заменять содержимым с допустимой меткой версии.

* Параметры передаются в виде HTTP Multipart-формы

    * `path`: путь к файлу относительно пути рабочей области
    * `isDir`: создавать ли папку; при `true` создаётся только папка, а `file` игнорируется
    * `modTime`: время последнего доступа и изменения, Unix time
    * `file`: загружаемый файл
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

## Сеть

### Прямой прокси

#### Прямой JSON-прокси

* `/api/network/forwardProxy`
* Параметры

  ```json
  {
    "url": "https://b3log.org/siyuan/",
    "method": "GET",
    "timeout": 7000,
    "contentType": "text/html",
    "headers": [
        {
            "Cookie": ""
        }
    ],
    "redirect": true,
    "payload": {},
    "payloadEncoding": "json",
    "responseEncoding": "text"
  }
  ```

    * `url`: перенаправляемый URL
    * `method`: HTTP-метод, по умолчанию `POST`
    * `timeout`: тайм-аут в миллисекундах, по умолчанию `7000` мс
    * `contentType`: HTTP Content-Type, по умолчанию `application/json`
    * `headers`: массив HTTP-заголовков запроса; пары ключ-значение в каждом объекте устанавливаются как заголовки запроса
    * `redirect`: следовать ли перенаправлениям, по умолчанию `true`, максимум 2 раза; при `false` перенаправления не выполняются
    * `payload`: тело HTTP-запроса, может быть объектом или строкой
    * `payloadEncoding`: схема кодирования, используемая для `payload`, по умолчанию `json`; при `json` `payload` отправляется напрямую, для двоичного тела запроса можно использовать следующие строки кодирования:

        * `json`
        * `base64` | `base64-std`
        * `base64-url`
        * `base32` | `base32-std`
        * `base32-hex`
        * `hex`
    * `responseEncoding`: схема кодирования, используемая для поля `body` в данных ответа, по умолчанию `text`; возможные значения:

        * `text`
        * `base64` | `base64-std`
        * `base64-url`
        * `base32` | `base32-std`
        * `base32-hex`
        * `hex`

      `text` сохраняет текущее поведение и при необходимости преобразует кодировку символов в UTF-8. Двоичное кодирование применяется к данным тела ответа до преобразования кодировки символов; текущее поведение декодирования HTTP-содержимого, например распаковка gzip, не изменяется.

      Максимальный размер тела ответа после декодирования HTTP-содержимого составляет 32 МиБ; при превышении возвращается код ошибки `10` без возврата частичного тела. Поэтому для больших файлов или потоковых ответов используйте `/api/network/proxy`.
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "body": "",
      "bodyEncoding": "text",
      "contentType": "text/html",
      "elapsed": 1976,
      "headers": {
      },
      "status": 200,
      "url": "https://b3log.org/siyuan/"
    }
  }
  ```

    * `body`: тело ответа
    * `bodyEncoding`: схема кодирования, используемая для `body`, совпадает с полем `responseEncoding` в запросе, по умолчанию `text`; возможные значения:

        * `text`
        * `base64` | `base64-std`
        * `base64-url`
        * `base32` | `base32-std`
        * `base32-hex`
        * `hex`
    * `contentType`: заголовок ответа `Content-Type`
    * `elapsed`: длительность запроса в миллисекундах
    * `headers`: заголовки ответа, возвращённые целевым сервисом
    * `status`: HTTP-код состояния, возвращённый целевым сервисом
    * `url`: перенаправленный URL

#### Прямой HTTP-прокси

* `/api/network/proxy`
* Метод запроса: любой HTTP-метод
* Параметры запроса (query)

    * `u`: обязательно, целевой URL `http` или `https`, закодированный с помощью `base64.RawURLEncoding` из Go (URL-безопасный Base64 без заполнения `=`)
    * `h`: необязательно, JSON заголовков запроса, закодированный тем же способом; тип JSON — `map[string][]string`, например `{"Authorization":["Bearer token"]}`
    * `t`: необязательно, тайм-аут подключения в формате Go `time.ParseDuration`, например `30s`, `1500ms`
* Тело запроса: текущее тело запроса пересылается без изменений; полный заголовок `Content-Type` текущего запроса пересылается в целевой запрос
* Возвращаемое значение: напрямую возвращаются HTTP-код состояния и тело ответа целевого сервиса без обёртки `code`, `msg`, `data`; к заголовкам ответа целевого сервиса добавляется префикс `Siyuan-Proxy-`, например `Content-Type` возвращается как `Siyuan-Proxy-Content-Type`

#### Прямой WebSocket-прокси

* `/ws/network/proxy`
* Метод запроса: `GET`
* Параметры запроса (query)

    * `u`: обязательно, целевой URL `ws` или `wss`, закодированный с помощью `base64.RawURLEncoding` из Go
    * `h`: необязательно, JSON заголовков рукопожатия, закодированный тем же способом; тип JSON — `map[string][]string`
    * `t`: необязательно, тайм-аут рукопожатия в формате Go `time.ParseDuration`, например `30s`, `1500ms`
* Возвращаемое значение: после обновления до WebSocket сообщения пересылаются в обоих направлениях; к заголовкам ответа рукопожатия целевого сервиса добавляется префикс `Siyuan-Proxy-`

#### Прямой EventSource-прокси

* `/es/network/proxy`
* Метод запроса: `GET`
* Параметры запроса (query)

    * `u`: обязательно, целевой URL `http` или `https`, закодированный с помощью `base64.RawURLEncoding` из Go
    * `h`: необязательно, JSON заголовков запроса, закодированный тем же способом; тип JSON — `map[string][]string`
    * `t`: необязательно, тайм-аут подключения в формате Go `time.ParseDuration`, например `30s`, `1500ms`
* Возвращаемое значение: HTTP-код состояния и тело ответа целевого сервиса передаются потоком напрямую без обёртки `code`, `msg`, `data`; если в заголовках запроса отсутствует `Accept`, автоматически используется `text/event-stream`; к заголовкам ответа целевого сервиса добавляется префикс `Siyuan-Proxy-`

## База данных

База данных (в ядре — «представление атрибутов», Attribute View) хранит структурированные данные в виде полей (столбцов) и записей (строк). Каждая база данных идентифицируется по `avID` и может быть встроена в документ через один или несколько блоков базы данных (`blockID`). Одна база данных может содержать несколько представлений (`viewID`) с различными типами макета: `table` (таблица), `list` (список), `gallery` (галерея/карточки) и `kanban` (канбан).

Типы полей (`keyType`):

| Значение | Описание |
|----------|----------|
| `block` | Первичный ключ (привязанный блок) |
| `text` | Текст |
| `number` | Число |
| `date` | Дата |
| `select` | Одиночный выбор |
| `mSelect` | Множественный выбор |
| `url` | URL |
| `email` | Эл. почта |
| `phone` | Телефон |
| `location` | Местоположение |
| `mAsset` | Ресурсы |
| `template` | Шаблон |
| `created` | Время создания |
| `updated` | Время обновления |
| `checkbox` | Флажок |
| `relation` | Связь |
| `rollup` | Сводка (Rollup) |
| `lineNumber` | Номер строки |

### Рендеринг

* `/api/av/renderAttributeView`

Ошибки разбора или вычисления обычных HTTP-шаблонов возвращаются в соответствующем поле, при этом база данных продолжает отображаться; отмена, блокировка блокнота и превышение лимита выполнения по-прежнему прерывают рендеринг.

По умолчанию `deferHTTPTemplates` равен `false`. При значении `true` сначала возвращается представление без выполнения сетевых шаблонов, а `pendingHTTPTemplates` перечисляет ID полей, ожидающих вычисления; шаблоны в той же базе данных также откладываются. Когда фильтрация, группировка, статистика, календарь или вложенный макет зависят от результатов шаблона, возвращается только структура без временного набора строк. Когда от шаблона зависит только сортировка, записи возвращаются сразу, а порядок определяется после завершения запроса. Повторный запрос без этого флага получает итоговый результат и подтверждает сетевой доступ по обычной процедуре. По умолчанию `preserveHTTPResults` равен `false`; в сочетании с `automaticRefresh: true` операции отображения, такие как сортировка и поиск, могут повторно использовать текущий успешный снимок шаблона, включая шаблоны, читающие внешние блоки или SQL. Границы источников, строкового ввода, прав доступа и кэша продолжают действовать; установка этого флага отдельно не отменяет ручное обновление.

* Параметры

  ```json
  {
    "id": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t",
    "viewID": "",
    "page": 1,
    "pageSize": 50,
    "query": "",
    "groupPaging": {},
    "targetItemID": "",
    "targetGroupID": "",
    "createIfNotExist": true,
    "persistView": true
  }
  ```

    * `id`: ID базы данных
    * `blockID`: блок базы данных, в который встроена эта база данных; используется для определения текущего представления, прав публикации и контекстной фильтрации на уровне блока. Если `custom-sy-av-view` отсутствует или недействителен, используется первое доступное представление. При рендеринге независимой базы данных можно опустить; при настроенной контекстной фильтрации необходимо передать действительный экземпляр блока базы данных
    * `viewID`: явное указание представления для рендеринга. При недействительном значении возвращается ошибка; при пропуске сначала определяется через `blockID`, а если определить не удаётся — используется первое доступное представление
    * `page`: номер страницы, начиная с 1. По умолчанию `1`
    * `pageSize`: количество записей на странице. `-1` или пропуск означает использование значения по умолчанию для представления (`50`)
    * Необязательный параметр `automaticRefresh`, по умолчанию `false`. При включении интерактивного выполнения шаблонов `true` повторно использует успешные результаты в памяти только для строк, у которых источник, шаблон и его ссылочные входные данные не изменились. Для ручного обновления следует опустить или передать `false`. Блокировка блокнота или отзыв разрешения шаблона очищают эти результаты; эта опция не расширяет права на чтение
    * `query`: необязательное ключевое слово для полнотекстовой фильтрации по значениям первичного ключа
    * `groupPaging`: необязательная конфигурация пагинации для сгруппированного (канбан) представления
    * `targetItemID`: необязательный ID искомой записи базы данных. При указании в возвращаемое значение включается информация о позиционировании цели
    * `targetGroupID`: необязательная подсказка группы, используемая совместно с `targetItemID`
    * `nested`: необязательный запрос древовидного чтения для табличных и списочных представлений с включёнными родительско-дочерними записями и древовидным отображением; при пропуске сохраняется плоский вывод. `expandedIDs` управляет раскрытыми элементами, `groupExpandedIDs` позволяет переопределять по группам; `childPaging` использует `parentID` (внутри группы — `groupID/parentID`), сопоставленный с `{page, pageSize}`, нумерация страниц с 1, максимум 200 дочерних элементов на страницу. Корневые записи используют пагинацию `page`/`pageSize`. В ответе `view.nested` возвращает фактический номер страницы, количество корней и количество совпавших записей, а `rows[].hierarchy` обозначает видимую иерархию и предков, используемых только для контекста. Позиционирование раскрывает предков и переключается на соответствующую страницу, не возвращая идентификаторы недоступных предков
    * `temporarySort`: необязательная сортировка по одному полю, например `{"column":"field-id","order":"DESC"}`. При пропуске или `null` используются сохранённые правила; при указании переопределяет сортировку только для этого запроса, применяется до пагинации, не создаёт и не сохраняет базу данных и не изменяет представление носителя по умолчанию. `order` должен быть `ASC` или `DESC`; при отсутствии поля или неподдерживаемой сортировке восстанавливаются сохранённые правила. Поддерживаются существующие параметры `valueSource` и `dateEndpoint`
    * `relationContext`: необязательная область деталей записи: `{"sourceAvID":"ID исходной БД","sourceItemID":"ID исходной записи","relationKeyID":"ID поля связи"}`. В исходном поле должна быть включена конфигурация представления связей, а `id` должен совпадать с целевой базой данных этого поля. При передаче `blockID` это должен быть реальный блок исходной базы данных или блок, привязанный к исходной записи; нельзя подменять ID блока на ID записи; для непривязанной записи можно передать пустое значение. Этот режим поддерживает только плоскую таблицу и не принимает `nested`. Явный `viewID` может выбрать существующее табличное представление в той же целевой базе данных; при пропуске используется представление, настроенное в поле. Если исходная база данных, поле или представление недействительны или недоступны, возвращается ошибка без отката к показу всей целевой базы данных. Запросы читателей в режиме публикации не поддерживают этот режим
    * `temporaryFilters`: необязательные дополнительные правила фильтрации в режиме `relationContext`, объединяемые по AND с сохранёнными фильтрами целевого представления только для этого запроса. Текущая область связанных участников исходной записи принудительно применяется до фильтрации, сортировки, группировки, пагинации, подсчёта и позиционирования целевой записи. Фильтрация кандидатов при добавлении связей не исключает существующих связанных участников. Этот режим рендеринга не сохраняет область участников, дополнительные фильтры, временную сортировку или выбор представления; недействительная временная сортировка возвращает ошибку
    * `createIfNotExist`: при `true` (по умолчанию), если база данных не существует, создаётся база данных с представлением по умолчанию
    * `persistView`: устаревший параметр совместимости. Интерфейс по-прежнему принимает этот параметр, но игнорирует его, так как определение базы данных больше не хранит текущее представление верхнего уровня

### Установить контекстную фильтрацию блока базы данных

* `/api/av/setAttrViewContextFilter`
* Параметры

  ```json
  {
    "avID": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t",
    "keyID": "20240118120300-relation"
  }
  ```

    * `avID`: ID базы данных
    * `blockID`: ID конкретного блока базы данных, для которого изменяется контекстная фильтрация; должен быть экземпляром `avID`
    * `keyID`: ID настроенного поля связи в базе данных; семантика фильтрации фиксирована и эквивалентна `Содержит любой - Текущий документ`. Передача пустой строки отключает контекстную фильтрацию
* Возвращаемое значение: нормализованная конфигурация в `data.contextFilter`; после отключения равна `null`

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "contextFilter": {
        "spec": 1,
        "keyID": "20240118120300-relation"
      }
    }
  }
  ```

При сохранении новых областей через `setAttrViewAutomations` общее количество уникальных блокнотов и документов не должно превышать 32. Существующие области сверх лимита по-прежнему можно читать и использовать, сохранять или удалять; добавление новых областей сверх лимита отклоняется. Отмена/повтор сохраняет исходные области. Основной тип включает все подтипы; формат 3 поддерживает `h:h1`–`h:h6`, `l:u/o/t`, `i:u/o/t` и `callout:TYPE` (с учётом регистра, допускаются пользовательские типы выносок). Пустой тип означает отсутствие ограничений, при нескольких типах срабатывает любое совпадение. Автоматически созданное значение первичного ключа может содержать `block.collectionRuleID`, поддерживаемый ядром. Автоматический сбор только добавляет записи; при изменении исходного текста, а также условий, области, объекта или состояния включения правила существующие записи и поля сохраняются, а повторное совпадение использует исходную запись. Активная очистка проверяет как вручную, так и автоматически привязанные записи по всем включённым правилам сбора, сохраняя совпадающие или неопределимые записи, и после повторной проверки перед выполнением удаляет только явно несовпадающие записи; отмена восстанавливает исходную запись и все поля. `blockSource.tagMatch` и `attributeMatch` по умолчанию имеют значение `and`, формат 3 поддерживает независимую настройку `or` для каждой группы; между группами по-прежнему применяется «И», пустая группа не ограничивает. Необязательный `notifyOnSuccess` для каждого правила по умолчанию или при `null` равен `true`, объединяя уведомления о фактических изменениях после успешной фиксации транзакции; отключение не влияет на сообщения об ошибках. При отсутствии изменений, ручном сборе, отмене/повторе и откате транзакции уведомление об успехе не отправляется. Формат 4 добавляет необязательный `blockSource.tagTarget`: пропуск или пустая строка использует выбор по умолчанию, отдавая приоритет сбору подходящего элемента списка вместо его первого блока содержимого; `block` собирает блок, в котором находится тег; `container` выбирает ближайший контейнер, соответствующий условиям типа и атрибутов, и дедуплицирует по ID блока; для документа необходимо явно выбрать `d`. Все теги должны находиться в одном исходном блоке; при отсутствии условий по тегам эта опция не влияет на фильтрацию. Предпросмотр соответствует фактически собираемому объекту, а переключение сохраняет существующие записи и поля. Формат 5 добавляет необязательный `blockSource.documentDepth`: пропуск или `null` означает отсутствие ограничений, `0` включает только сам каждый выбранный документ, `1` также включает дочерние документы первого уровня, а другие неотрицательные целые числа задают максимальную относительную глубину потомков. Эта настройка единообразно ограничивает область документов, не влияет на область блокнотов, а области по-прежнему объединяются. Изменение глубины сохраняет существующие записи и поля без автоматического досбора существующего содержимого. Формат 6 добавляет необязательный `nameOperator` для каждого условия атрибута: пропуск, пустая строка или `equals` сохраняют точное совпадение полного имени, `contains` ищет буквальную подстроку без необходимости ввода префикса `custom-`, а `regex` использует синтаксис регулярных выражений Go для сопоставления полного имени, включая этот префикс. Сопоставляются только пользовательские атрибуты, имена и значения чувствительны к регистру и должны одновременно выполняться одним и тем же атрибутом; `exists` требует совпадения хотя бы одного имени, `notExists` — отсутствия совпадений имён, оба игнорируют значение атрибута. Шаблон имени ограничен 256 байтами, недопустимые регулярные выражения отклоняются при сохранении. Поведение существующих форматов 1–5 остаётся неизменным, старые читатели отклоняют формат 6 без изменения базы данных. Формат 7 добавляет необязательный `blockSource.includeSelectedDocuments`: пропуск, `null` или `true` включает сам каждый выбранный документ; `false` исключает этот документ и все блоки внутри него, при этом дочерние документы по-прежнему сопоставляются согласно `documentDepth`. Эта настройка является общей для всех областей документов, не влияет на области блокнотов или другие перекрывающиеся области документов, а области по-прежнему объединяются. При сочетании `false` с глубиной `0` соответствующая область документов пуста. После изменения существующие записи и поля сохраняются без автоматического досбора или удаления. Форматы 1–6 по-прежнему читаемы, старые читатели отклоняют формат 7 без изменения базы данных. Формат 8 добавляет необязательный `blockSource.referenceID`: сопоставляет ссылки на блоки в основном тексте, указывающие на этот блок; цель-документ также включает внутренние блоки содержимого, без дочерних документов; не включает встроенные блоки, обычные ссылки и ссылки в форматированных текстовых полях базы данных. Теги ограничивают тот же исходный блок ссылки, источники объединяются по правилам родительского блока обратных ссылок перед сопоставлением типа и атрибутов, `tagTarget` в выборе не участвует. Цель должна находиться в той же границе шифрования. Сам автоматический сбор сохраняет существующие записи и поля после удаления ссылки или изменения цели, а историческое содержимое требует явного досбора после предпросмотра. При удалении ссылки на блок основного текста в редакторе после подтверждения можно синхронно удалить автоматически собранные записи, которые явно больше не соответствуют ни одному включённому правилу сбора; ручные записи, записи, всё ещё соответствующие какому-либо включённому правилу, и неопределимые записи сохраняются, а отмена атомарно восстанавливает удалённую ссылку, исходную запись и значения полей. Форматы 1–7 по-прежнему читаемы, старые клиенты отклоняют формат 8 без изменения базы данных. Формат 9 добавляет явный триггер `manual`: включённые и сохранённые правила обрабатывают подходящие сохранённые записи только при интерактивном ручном выполнении; шаблоны поддерживают `httpGet` и строгий `fromJson`, следуя существующим правам HTTP и бюджетам выполнения. После успешного выполнения всех запросов и преобразований типов результаты атомарно записываются в обычные поля без удержания блокировки транзакции редактирования во время ожидания сети. Изменение исходной или целевой базы данных отклоняет выполнение, а при сбое сохраняются исходные значения. Все действия читают снимок хранилища на момент начала выполнения, отмена/повтор используют сохранённые результаты без выполнения HTTP-запросов или каскадирования автоматизаций. За один раз выполняется максимум 1 000 записей полей и добавлений записей; выполнение по расписанию или постоянное кэширование результатов шаблонов не предусмотрены. Форматы 1–8 по-прежнему читаемы, старые клиенты отклоняют формат 9 без изменения базы данных. Формат 10 добавляет ограниченные `printf`, `urlquery`, `dict`, `toString`, а также `fromJson`/`httpGet` в шаблонах событий. Вся правило с HTTP выполняется после фиксации редактирования только для вызвавшей его записи, а результат фиксируется и отменяется отдельно; при сбое сохраняются правка и исходный результат. Активное главное окно, инициировавшее редактирование, продолжает однократную задачу из ответа транзакции; записи через API без окна не выполняют правила с HTTP. Последовательные правки объединяются, устаревшие результаты отбрасываются, а отмена/повтор не обращаются к сети повторно. Форматирование поддерживает до 64 параметров, сериализованный ввод и строковый вывод — до 64 КиБ; `printf` ограничивает ширину и точность скалярных параметров, не поддерживает динамическую ширину или индексацию параметров, а `dict` требует строковых ключей и полных пар ключ-значение. Существующие форматы 1–9 (включая отключённые незавершённые шаблоны) по-прежнему читаемы, старые клиенты отклоняют формат 10 без изменения источника.

      Интерфейс ручного выполнения включает построчное выполнение при `rows: true`; существующие вызовы сохраняют атомарное выполнение всей партии и ответ `null`. Сначала начните с пустого `runID`, затем продолжайте партию с `runID` и `step`; `status` только запрашивает прогресс, повторный порядковый номер не воспроизводит действия. Каждая партия обрабатывает до 32 подходящих записей, все действия для каждой записи фиксируются атомарно. `code 1` возвращает частичный прогресс, включая ID успешных, сбойных, ожидающих и пропущенных записей. Все партии совместно используют один сетевой бюджет и лимит в 1 000 операций; явный `retry` начинает новый раунд только для сбойных и незавершённых записей. Прогресс привязан к главному окну, действителен в течение 15 минут, не содержит открытого текста полей и очищается при начале блокировки блокнота. Редактор шаблонов поддерживает выбор по имени, вставку стабильных ссылок на поля и копирование ID полей.

### Установить значение ячейки

Обновляет одну ячейку (определённое поле определённой строки). Это основной интерфейс записи значений ячеек. `value` в запросе — это частичный объект `Value`, структура которого зависит от `keyType` поля. Распространённые структуры `value`:

| `keyType` | Структура `value` |
|-----------|-------------------|
| `block` | `{"block": {"content": "Первая строка", "id": "<ID привязанного блока>"}, "isDetached": false}` |
| `text` | `{"text": {"content": "Текст"}}` |
| `text` (форматированный) | `{"text": {"content": "Текст", "rich": {"spec": 1, "format": "kramdown", "content": "**Текст**"}}}` |
| `number` | `{"number": {"content": 42, "isNotEmpty": true}}` (для очистки `{"isNotEmpty": false}`) |
| `date` | `{"date": {"content": 1676042451000, "isNotEmpty": true}}` (метка времени в мс) |
| `select` | `{"mSelect": [{"content": "Выполнено", "color": "1"}]}` (не более одного варианта) |
| `mSelect` | `{"mSelect": [{"content": "A", "color": "1"}, {"content": "B", "color": "2"}]}` |
| `url` | `{"url": {"content": "https://siyuan.com"}}` |
| `email` | `{"email": {"content": "a@b.com"}}` |
| `phone` | `{"phone": {"content": "1234567890"}}` |
| `location` | `{"location":{"name":"Home","latitude":0,"longitude":0,"originalInput":"0, 0"}}` |
| `mAsset` | `{"mAsset": [{"type": "image", "name": "Изображение", "content": "https://example.com/image"}]}` |
| `checkbox` | `{"checkbox": {"checked": true}}` |

Для `mAsset` каждый элемент использует `type: "image"` для рендеринга изображения или `type: "file"` для рендеринга ссылки на файл. Обновление значения заменяет весь массив `mAsset`, поэтому при добавлении ресурса необходимо включать существующие элементы.

> ⚠️ `itemID` — это **ID записи**, то есть `id` записи, возвращаемый при [Рендеринге](#рендеринг): для таблицы и списка это `rows[].id`, для карточек и канбана — `cards[].id`, а при включённой группировке он находится в соответствующем экземпляре представления в `groups[]`. Он также равен `value.blockID` значения первичного ключа. Для привязанной записи ID привязанного блока находится в `value.block.id` значения первичного ключа; это разные понятия, и нельзя предполагать, что они равны. Передача неверного ID сохранит значение как «осиротевшие» данные, которые не отобразятся в отрендеренной ячейке.

Для форматированного текста `text.rich.content` является авторитетным источником Kramdown. Ядро проверяет поддерживаемую структуру и выводит проекцию обычного текста `text.content`; проекция обычного текста, переданная вызывающей стороной, игнорируется. Для совместимости с существующими API-клиентами при пропуске `text.rich`, если `text.content` не изменился, сохранённая форматированная нагрузка сохраняется, а если `text.content` изменился — заменяется обычным текстом. Даже если проекция обычного текста не изменилась, можно отправить `"rich": null` для явного удаления форматирования. Форматированные текстовые поля требуют спецификацию хранения 9 или выше. Сохранение строчных изображений (например, `![Фото](assets/photo.png)`) в текстовом поле требует спецификацию 17. Старые ядра не смогут открыть базы данных, использующие более высокую спецификацию.

Поле `name` в `location` необязательно. `latitude` и `longitude` должны либо оба отсутствовать или быть `null`, либо оба быть конечными числами в диапазонах `[-90, 90]` и `[-180, 180]` соответственно; ноль является допустимой координатой. Все координаты неявно используют WGS84 и не преобразуются автоматически при сохранении. Значение местоположения не принимает явное свойство системы координат, и для поля не предусмотрена настройка системы координат по умолчанию. `originalInput` сохраняет исходный текст и не участвует в фильтрации и сортировке. Пропуск элементов при обновлении сохраняет существующие значения; для очистки местоположения можно отправить `{"location":null}` либо явно очистить имя и установить обе координаты в `null`. При изменении координат пропущенный `originalInput` автоматически очищается; явно переданный исходный текст сохраняется. Текстовый поиск использует `{"type":"location","text":{"content":"поисковый запрос"}}`, сопоставляя имя и координаты. Поле местоположения использует версию хранения базы данных 13, которую старые ядра не могут открыть; базы данных, не использующие поле местоположения, сохраняют прежнюю версию хранения.

Первичный ключ (`block`) сохраняет источник `kramdown` версии 1 через `block.rich`, структура блока соответствует текстовому полю и поддерживает изображения. Существующие источники `inline-ast` версии 1 по-прежнему читаемы и не преобразуются автоматически. `block.richBlockDOM` — это фрагмент рендеринга времени выполнения; интерфейс обновления ячейки проверяет поддерживаемые фрагменты блоков и преобразует отредактированное содержимое в источник хранения; при одновременной отправке обеих форм содержимое должно совпадать. `block.content` — производная проекция обычного текста. При пропуске поля форматированного текста и неизменной проекции источник сохраняется; для замены форматированного первичного ключа обычным текстом необходимо явно передать `block.rich: null` и опустить `richBlockDOM`. Редактирование привязанного первичного ключа задаёт статический текст якоря без переписывания исходного документа; очистка обычного текста восстанавливает динамический источник. Сохранение первичного ключа Kramdown требует спецификации базы данных 16, старый строчный источник — спецификации 15; неотредактированные базы данных сохраняют прежнюю версию. Старые клиенты не могут открыть базу данных формата 16, для отката требуется восстановление полного снимка до обновления.

### Добавить запись

Добавляет одну или несколько записей (строк). Каждый источник может либо привязывать существующий блок (`isDetached: false`), либо создавать независимую строку, существующую только внутри представления (`isDetached: true`).

* `/api/av/addAttributeViewBlocks`
* Параметры

  ```json
  {
    "avID": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t",
    "viewID": "",
    "groupID": "",
    "previousID": "",
    "srcs": [
      {
        "id": "20240118120201-kldj15t",
        "isDetached": false,
        "content": "Новая строка"
      }
    ],
    "ignoreDefaultFill": false
  }
  ```

    * `avID`: ID базы данных
    * `blockID`: блок базы данных, владеющий этой базой данных (используется для определения целевого представления/группы)
    * `viewID`: явное указание целевого представления. При пропуске используется представление, выбранное через `blockID`; если определить не удаётся — используется первое доступное представление
    * `groupID`: ID целевой группы для представления канбан. Для табличного/карточного представления можно опустить
    * `previousID`: вставить после этого ID записи. Пустое значение означает добавление в конец
    * `srcs[].id`: при привязке блока (`isDetached: false`) — ID привязываемого блока, должен соответствовать формату ID узла
    * `srcs[].isDetached`: `true` создаёт независимую строку; `false` привязывает существующий блок
    * `srcs[].content`: отображаемый текст первичного ключа (используется при `isDetached: true` или переопределяет содержимое привязанного блока)
    * `srcs[].itemID`: необязательно, явное указание ID записи. При пропуске генерируется автоматически
    * `ignoreDefaultFill`: при `true` пропускает автоматическое заполнение значений по умолчанию для полей фильтрации/группировки
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```

    * Этот интерфейс возвращает `null`; после успеха вызовите [Рендеринг](#рендеринг) для получения обновлённых строк (включая новый ID строки, необходимый для обновления ячеек)

### Переключить макет

Переключает тип макета выбранного представления блока базы данных между `table` (таблица), `list` (список), `gallery` (карточки) и `kanban` (канбан). При успехе сервер повторно рендерит и возвращает представление (структура совпадает с [Рендеринг](#рендеринг)).

При первом переключении на `list` инициализируется независимый макет, где по умолчанию отображается только поле первичного ключа. Последующее переключение обратно на этот макет сохраняет видимость и порядок полей. Значения скрытых полей остаются неизменными и по-прежнему могут использоваться для фильтрации и сортировки; другие макеты сохраняют свои настройки отображения.

* `/api/av/changeAttrViewLayout`
* Параметры

  ```json
  {
    "avID": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t",
    "layoutType": "kanban"
  }
  ```

    * `avID`: ID базы данных
    * `blockID`: блок базы данных, владеющий этим представлением
    * `layoutType`: целевой макет — один из `table`, `list`, `gallery`, `kanban`
* Возвращаемое значение: структура совпадает с возвращаемой при [Рендеринге](#рендеринг). При переключении на `kanban` с настроенной группировкой `data.view` содержит массив `groups[]`; каждая группа является экземпляром представления и содержит `groupKey`, `groupValue`, а также специфичные для канбана поля (`coverFrom`, `cardAspectRatio`, `cardSize`, `fitImage`, `displayFieldName`, `fillColBackgroundColor`, `fields`)

### Настроить группировку

Устанавливает или очищает правило группировки для представления канбан. Когда `group.field` пуст, группировка удаляется. При успехе сервер повторно рендерит и возвращает представление.

* `/api/av/setAttrViewGroup`
* Параметры

  ```json
  {
    "avID": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t",
    "group": {
      "field": "20240118203822-io6ofxb",
      "method": 0,
      "order": 0,
      "hideEmpty": false
    }
  }
  ```

    * `avID`: ID базы данных
    * `blockID`: блок базы данных, владеющий этим представлением
    * `group`: правило группировки
    * `group.field`: ID поля (столбца) для группировки. Пустая строка означает удаление группировки
    * `group.valueSource`: необязательный источник значений — `stored` использует сохранённое значение поля (по умолчанию при пропуске); `rendered` использует результат шаблона отображения поля и группирует по текстовому значению
    * `group.method`: способ группировки — `0` по значению, `1` по числовому диапазону, `2` по относительной дате, `3` по дню, `4` по неделе, `5` по месяцу, `6` по году
    * `group.range`: необязательно. Обязательно при `method`, равном `1` (числовой диапазон): `{ "numStart": 0, "numEnd": 100, "numStep": 10 }`
    * `group.order`: сортировка групп — `0` по возрастанию, `1` по убыванию, `2` вручную, `3` по порядку вариантов
    * `group.hideEmpty`: скрывать ли пустые группы
* Возвращаемое значение: структура совпадает с возвращаемой при [Рендеринге](#рендеринг)

### Получить фильтрацию и сортировку
Возвращает текущие правила фильтрации и сортировки представления, привязанного к блоку базы данных.

* `/api/av/getAttributeViewFilterSort`
* Параметры

  ```json
  {
    "id": "20240118120204-kwyzf77",
    "blockID": "20240118120201-kldj15t"
  }
  ```

    * `id`: ID базы данных
    * `blockID`: блок базы данных, владеющий этим представлением
* Возвращаемое значение (реальный ответ, фильтрация/сортировка не настроены):

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "filters": [],
      "sorts": []
    }
  }
  ```

  После настройки (реальный полученный ответ) фильтрация и сортировка выглядят следующим образом:

  ```json
  {
    "code": 0,
    "msg": "",
    "data": {
      "filters": [
        {
          "column": "20240118203822-io6ofxb",
          "operator": "=",
          "value": {
            "type": "select",
            "mSelect": [
              { "content": "Выполнено", "color": "1" }
            ]
          }
        }
      ],
      "sorts": [
        {
          "column": "20240118120204-w6cggab",
          "order": "DESC"
        }
      ]
    }
  }
  ```

    * `data.filters`: массив `ViewFilter`. Верхний уровень — один корневой узел группы `{ "combination": "and"|"or", "filters": [...] }`; элементами массива могут быть как листовые условия фильтрации, так и вложенные узлы групп, поддерживающие рекурсивную комбинацию И/ИЛИ
    * `data.filters[].column`: ID поля (столбца), к которому применяется правило фильтрации (только для листовых узлов)
    * `data.filters[].valueSource`: необязательный источник значений для листового узла — при пропуске по умолчанию `stored`, `rendered` означает фильтрацию по результату шаблона отображения поля
    * `data.filters[].operator`: оператор фильтрации (см. таблицу операторов ниже; только для листовых узлов)
    * `data.filters[].value`: операнд фильтрации, объект `Value` (структуру см. в [Установить значение ячейки](#установить-значение-ячейки); только для листовых узлов). Когда `valueSource` равен `rendered`, используется значение шаблона вида `{ "type": "template", "template": { "content": "..." } }`
    * `data.filters[].relativeDate`: необязательно, описание относительного времени для фильтрации по дате (`{ "count": 7, "unit": 0, "direction": -1 }`; `unit`: `0` день, `1` неделя, `2` месяц, `3` год; `direction`: `-1` назад, `0` текущий, `1` вперёд; только для листовых узлов)
    * `data.filters[].combination`: способ объединения группы, `"and"` или `"or"` (только для узлов групп)
    * `data.filters[].filters`: дочерние узлы фильтрации, рекурсивный `ViewFilter` (только для узлов групп)
    * `data.sorts`: массив `ViewSort`
    * `data.sorts[].column`: ID поля (столбца), к которому применяется правило сортировки
    * `data.sorts[].valueSource`: необязательный источник значений — при пропуске по умолчанию `stored`, `rendered` означает сортировку по результату шаблона отображения поля
    * `data.sorts[].order`: `ASC` или `DESC`

  Операторы фильтрации:

  | Значение | Описание |
  |----------|----------|
  | `=` | Равно |
  | `!=` | Не равно |
  | `>` | Больше |
  | `>=` | Больше или равно |
  | `<` | Меньше |
  | `<=` | Меньше или равно |
  | `Contains` | Содержит |
  | `Does not contains` | Не содержит |
  | `Is empty` | Пусто |
  | `Is not empty` | Не пусто |
  | `Starts with` | Начинается с |
  | `Ends with` | Заканчивается на |
  | `Is between` | Между |
  | `Is true` | Истина (флажок) |
  | `Is false` | Ложь (флажок) |

## Поиск

Сохранённые группы условий поиска используют следующие поля:

* `name`: название группы условий, также является уникальным ключом группы условий
* `sort`: способ сортировки результатов: `0` — по типу блока, `1` — по времени создания по возрастанию, `2` — по времени создания по убыванию, `3` — по времени обновления по возрастанию, `4` — по времени обновления по убыванию, `5` — по порядку содержимого, `6` — по релевантности по возрастанию, `7` — по релевантности по убыванию
* `group`: способ группировки: `0` — без группировки, `1` — группировка по документу
* `hasReplace`: включена ли замена
* `method`: способ поиска: `0` — по ключевому слову, `1` — синтаксис запросов, `2` — SQL, `3` — регулярное выражение, `4` — семантический поиск
* `hPath`: человекочитаемый путь области поиска
* `idPath`: массив путей области поиска
* `k`: ключевое слово поиска
* `r`: ключевое слово замены
* `types`: переключатели типов блоков; поддерживаются `mathBlock`, `table`, `blockquote`, `superBlock`, `paragraph`, `document`, `heading`, `list`, `listItem`, `codeBlock`, `htmlBlock`, `embedBlock`, `databaseBlock`, `audioBlock`, `videoBlock`, `iframeBlock`, `widgetBlock`, `callout`, `tabs` и `tabItem`
* `subTypes`: независимые группы подтипов; `heading` использует `h1`–`h6`, `list` и `listItem` используют соответственно `o` (упорядоченный), `u` (неупорядоченный) и `t` (задача). Если группа отсутствует, пуста или все переключатели равны `false`, подтипы данного родительского типа не ограничиваются; родительский тип всё равно должен быть включён в `types`. Неизвестные ключи верхнего уровня (включая `h1`–`h6` и `o`, `u`, `t` из старого плоского формата) игнорируются без ошибки; сохранённый выбор подтипов в старом формате необходимо выбрать и сохранить заново
* `replaceTypes`: переключатели типов замены; поддерживаются `text`, `imgText`, `imgTitle`, `imgSrc`, `aText`, `aTitle`, `aHref`, `code`, `em`, `strong`, `inlineMath`, `inlineMemo`, `blockRef`, `fileAnnotationRef`, `kbd`, `mark`, `s`, `sub`, `sup`, `tag`, `u`, `docTitle`, `codeBlock`, `mathBlock` и `htmlBlock`

Пропущенные логические переключатели в `types`, `subTypes` или `replaceTypes` обрабатываются как `false`.

### Получить сохранённые группы условий поиска

* `/api/storage/getCriteria`
* Без параметров
* Возвращаемое значение: `data` — массив групп условий поиска в порядке сохранения; при отсутствии сохранённых групп условий возвращается пустой массив
* Для роли только для чтения группы условий фильтруются согласно правам доступа при публикации, а поля `k` и `r` в возвращаемом результате очищаются

### Сохранить группу условий поиска

Создаёт группу условий или полностью перезаписывает группу условий с таким же именем. При перезаписи сохраняется исходная позиция, при добавлении — добавляется в конец.

* `/api/storage/setCriterion`
* Требуется роль администратора; недоступно в режиме только для чтения
* Параметры

  ```json
  {
    "criterion": {
      "name": "Публичные заметки",
  ```

### Удалить группу условий поиска

Удаляет группу условий с указанным именем. Если имя не существует, операция также считается успешной.

* `/api/storage/removeCriterion`
* Требуется роль администратора; недоступно в режиме только для чтения
* Параметры

  ```json
  {
    "name": "Публичные заметки"
  }
  ```

    * `name`: название группы условий
* Возвращаемое значение

  ```json
  {
    "code": 0,
    "msg": "",
    "data": null
  }
  ```
