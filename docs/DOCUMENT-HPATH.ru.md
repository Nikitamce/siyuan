# Переименование документов и индексация путей

При переименовании документа исходный документ сохраняется немедленно, а строка документа в базе данных дерева блоков (blocktree) обновляется синхронно. Позиционирование или создание документов по человекочитаемому пути по-прежнему использует актуальный путь документа. Копии `hpath` блоков содержимого в базе содержимого и базе дерева блоков обновляются постепенно в фоновом режиме; в течение этого времени SQL-запросы могут возвращать смешанные результаты со старыми и новыми путями.

## Способ обновления

- Обычное переименование не загружает содержимое потомков, не удаляет и не перестраивает деревья блоков потомков, а также не изменяет `.sy`-файлы потомков.
- Повторные переименования одного и того же документа объединяются; родительская задача может перекрывать пакетное обновление потомков, но для каждого переименованного исходного документа сохраняется отдельная запись восстановления.
- Строки документов находят через локальный индекс по блокноту и пути данных, чтобы не сканировать все блоки содержимого для оценки размера поддерева.
- Пакетные запросы к дереву блоков используют составной индекс `(root_id, box_id)`, ограничивая область сканирования текущим документом; при инициализации существующих обычных и зашифрованных баз данных индекс идемпотентно досоздаётся без изменения формата исходных документов.
- Фоновая задача выполняется не более ~20 мс за раз, обновляя максимум по 512 строк в каждой из двух баз данных за пакет, с динамической подстройкой от 32 до 512 строк по фактическому времени выполнения; одиночный запрос нельзя принудительно прервать, поэтому бюджет времени не является жёстким верхним пределом задержки.
- В каждом пакете дополнительно предзагружается одна строка для проверки наличия следующих данных: предзагруженная строка не записывается и не сдвигает курсор, а последний пакет сразу подтверждает завершение; база содержимого в том же запросе собирает ID блоков для очистки кэша; обе базы данных поддерживают отдельные курсоры и статусы завершения.
- Между пакетами транзакции и блокировки БД освобождаются; приоритет отдаётся обычному редактированию и очереди индексации, во время синхронизации фоновое обновление приостанавливается; по умолчанию планировщик запускается каждые 100 мс.
- Каждая задача хранит ссылку на перекрывающую её родительскую задачу и проверяет отношение перекрытия при планировании; раз в минуту по каждому блокноту проверяется, не исчез ли каталог — закрытые или заблокированные блокноты не считаются удалёнными.
- Перед выполнением пакета заново считываются позиция и путь документа, а под блокировкой записи дерева блоков проверяется снимок; обычные операции индексации используют текущий путь документа, чтобы старые элементы очереди не записали устаревший `hpath`.
- Перемещение по-прежнему идёт по прежнему сценарию: фоновое обновление путей не меняет принадлежность блокноту или реальный путь данных.

## Восстановление и совместимость с шифрованием

`temp/queue/hpath-refresh.queue` — локальный журнал задач версии `1`, находящийся на одном уровне с обычной очередью восстановления индекса и не участвующий в синхронизации данных заметок. Запись содержит только ID блокнота, ID документа и путь данных из ID, без заголовков, текста, ключей или курсоров блоков. Перед записью исходного документа запись предварительно сохраняется на диск, а очищается только после завершения всех пакетов в обеих базах данных; при пустой очереди файл удаляется. После прерывания процесса проверка начинается с начала, уже обновлённые строки повторно не перезаписываются.

При принудительном перестроении или обновлении структуры обычной базы данных сначала делаются недействительными оба старых индекса, а затем через `clearIndexQueueEntries()` синхронно очищаются дисковые записи и состояние в памяти соответствующих задач обновления путей, чтобы при сбое не оставались старые индексы с утерянной записью восстановления. Инициализация БД и задачи обновления путей используют общий мьютекс, причём блокировка задач обновления путей захватывается первой во избежание гонки между очисткой и записью и инверсии порядка блокировок. Задачи для отдельных зашифрованных баз данных сохраняются: перестроение обычного индекса не заменяет аутентификацию и восстановление зашифрованных исходных файлов. После успешного удаления каталога блокнота задачи этого блокнота очищаются немедленно; остатки от внешнего удаления или синхронизации собираются периодической проверкой.

При запуске сначала восстанавливаются метаданные документов для позиционирования из исходных документов, а затем в фоне дозаполняются пути блоков содержимого. Восстановительное чтение аутентифицирует зашифрованные файлы, проверяет формат и идентичность документа; при отсутствии, повреждении или ошибке аутентификации исходный файл и задача сохраняются, а родительский документ не досоздаётся. Для зашифрованных блокнотов каждый цикл фонового планирования удерживает аренду операции (lease), приостанавливается при блокировке и продолжается после разблокировки и построения индекса. Эти изменения не затрагивают формат шифротекста `.sy`, AAD, ключевой материал, историю, резервные копии или формат синхронизации.

В обычную очередь индексации добавлена операция `rename_doc`, которая своевременно обновляет только заголовок документа и строку документа. Существующие записи `rename` продолжают восстанавливаться прежним подокументным способом. Фоновая задача очищается независимо от пакетного снимка обычной очереди, чтобы запись восстановления не терялась после завершения лишь первого пакета.

## Регрессионная проверка

Выполните в `kernel/`:

```text
go test -tags "fts5 sqlcipher" ./model ./sql ./treenode ./filesys -run "Test(DocumentHPathRefresh|EncryptedDocumentHPathRefresh|IndexQueueRenameRecovery|ReadDocHPathDoesNotRepairSource|HPathRefresh)" -count=1
```

Эти тесты охватывают ограниченное обновление, определение завершения на полном и хвостовом пакетах, продвижение курсоров при разном числе строк в двух БД, отсутствие преждевременного обновления предзагруженной строки, миграцию существующих индексов и область сканирования запросов, сохранение идентичности файлов потомков и строк дерева блоков, создание документа по новому пути, повторные и родительско-дочерние переименования, старые снимки редактирования, восстановление после частичного обновления, восстановление при сохранённом исходном файле и необновлённых метаданных, ошибки записи в БД, перемещение, удаление, синхронизацию заголовков, блокировку и повторную разблокировку шифрования, неизменность шифротекста и сохранение исходных данных при ошибке аутентификации. Регрессионные тесты жизненного цикла очереди также покрывают сохранение повреждённых и неизвестных форматов, отсутствие очистки задач путей при сбросе обычной очереди, очистку при принудительном и структурном перестроении, взаимное исключение перестроения и записи задач, замену перекрывающих задач, восстановление после закрытия, сборку мусора при удалении и сохранение зашифрованных задач при перестроении обычного индекса. Они также входят в полную команду тестирования ядра в CI: `go test -tags "fts5 sqlcipher" ./... -count=1`.

Фоновые задачи, выполняющиеся дольше одной секунды, логируют число документов, число пакетов, общее время выполнения и фактическое время пакетов БД. При оценке производительности следует одновременно отслеживать время отклика на переднем плане, CPU и объём дискового ввода-вывода, не принимая общее время с учётом ожидания планировщика за время записи в базу данных.
