# Проектирование автономного редактора Markdown

Относится к [#21115](https://github.com/siyuan-note/siyuan/issues/21115). Редактор поставляется вместе с SiYuan и работает напрямую с внешними Markdown-файлами, авторизованными пользователем, без импорта в рабочую область и без использования `.sy`, синхронизации рабочей области или хранилища зашифрованных блокнотов. Внешние исходные файлы и черновики восстановления не получают из-за этого защиту шифрованием блокнота.

## Модули и запуск

- `app/src/markdown/`: общая страница редактирования, адаптер Vditor, конечный автомат сессии, политика ресурсов и нативный транспортный протокол
- `app/electron/markdown/`: маршрутизация запуска на рабочем столе, изолированное окно песочницы, дескрипторы авторизованных файлов, файловые транзакции и хранилище восстановления
- `app/webpack.markdown.js`, `app/scripts/markdown-assets.js`: автономная страница и манифест офлайн-ресурсов; артефакты сборки размещаются в `stage/build/markdown/`
- `MarkdownActivity` на Android, `MarkdownSceneDelegate` на iOS и `MarkdownAbility` на HarmonyOS: нативные автономные контейнеры, маршрутизирующие внешние Markdown-запросы до цепочки запуска рабочей области

Точка входа в основной рабочей области лишь отправляет запрос «создать новый автономный контейнер редактирования», не передавая странице редактирования права рабочей области. Лёгкая точка входа не запускает ядро Go; уже запущенные рабочая область и ядро продолжают работать по своему обычному жизненному циклу. При выходе из всего приложения необходимо дождаться сохранения и защиты восстановления для всех лёгких сессий; при уходе в фон выполняется только попытка сохранить уже зафиксированный ввод без показа диалога подтверждения выхода.

Когда на рабочем столе открыто только автономное окно Markdown, обычный запрос запуска всё равно может открыть главный интерфейс рабочей области. Чтение рабочей области и журналов сбоев происходит только после поступления этого запроса, с переиспользованием веток первого запуска, восстановления после сбоя, потери каталога и обычного запуска без изменения начального снимка запуска. Повторный запрос переиспользует существующую страницу выбора рабочей области или окно запуска ядра, а окно Markdown продолжает автономное редактирование.

Контейнер редактирования Android работает в процессе `:markdown` с отдельным каталогом данных WebView, и вызов `Mobile.exit()` рабочей области не завершает этот процесс. На iOS и HarmonyOS ядро Go по-прежнему слинковано внутри процесса приложения, поэтому отдельная scene или UIAbility не могут изолировать аварийное завершение всего процесса; обычное закрытие рабочей области откладывает выход из процесса. Отложенный запрос HarmonyOS привязывается к поколению рабочей области: после повторного открытия рабочей области старый запрос отменяется, а явный глобальный выход всё равно должен пройти защиту всех сессий. При аварийном завершении можно восстановить только ранее подтверждённые на диске черновики. При принудительной остановке всего приложения операционной системой также нельзя полагаться на обратный вызов выхода для сохранения последнего ввода.

Vditor зафиксирован на версии `4.0.2-alpha.1` с отключённым встроенным кэшем. Офлайн-манифест использует сборку Lute из репозитория, содержащую исправление round-trip для title определений ссылок, соответствующее коммиту исходного кода Lute `a824e50c`. При обновлении парсера необходимо сохранять round-trip-семантику title определений ссылок во всех трёх режимах редактирования; артефакт собирается из исходного кода Lute без прямого редактирования минифицированного файла и без возврата к неисправленному парсеру внутри пакета Vditor.

## Каталоги конфигурации и восстановления

Каталоги определяются хостом; мост не принимает пути конфигурации. Предпочтения редактирования включают режим, тему и размер шрифта; состояние отображения дерева файлов, его ширина и развёрнутые каталоги используют отдельное версионированное хранилище без вызова обычных интерфейсов конфигурации рабочей области. Настольный файл `tree-view.json` использует версию 1, ширину по умолчанию 240, допустимый диапазон 180–480; для каждого корня запоминается до 256 развёрнутых каталогов и до 16 последних корней; неизвестная версия или повреждённое содержимое сохраняются с выводом ошибки.

| Платформа | Изолированное пространство имён | Политика системного резервного копирования |
| --- | --- | --- |
| Рабочий стол | `markdown/` в корневом каталоге конфигурации приложения, по умолчанию `~/.config/siyuan/markdown/` | Не подключается к синхронизации SiYuan; резервное копирование ОС может включать этот каталог |
| Android | `Context.getExternalFilesDir(null)/home/.config/siyuan/markdown/` | Исключается из устаревшего резервного копирования, облачного резервного копирования и правил переноса устройств |
| iOS | `Documents/home/.config/siyuan/markdown/` | Устанавливается `isExcludedFromBackup` |
| HarmonyOS | `Context.filesDir/workspaces/home/.config/siyuan/markdown/` | Исключается в правилах резервного копирования приложения |

Мобильные платформы используют свои существующие эмулированные `home`, что позволяет определить каталог конфигурации без запуска ядра. Черновики и записи восстановления записи на всех платформах располагаются в `markdown/recovery/`, а предпочтения редактирования и состояние дерева файлов — в корне `markdown/`, сохраняя нативный формат хранения каждой платформы.

Предпочтения и записи восстановления имеют версию формата. Запись восстановления проверяет содержимое, целевое поколение записи и версию редактирования, подтверждая сохранение на диск только после безопасного обновления; неизвестные версии и повреждённые записи сохраняются в исходном виде и не перезаписываются значениями по умолчанию. Лимит хранилища восстановления составляет 256 МиБ и не более 1024 записей; несохранённое содержимое не вытесняется автоматически по времени, а при нехватке места возвращается ошибка. Пользователь может явно восстановить или очистить черновики неактивных сессий, но не может очищать записи восстановления, используемые другими контейнерами редактирования.

## Контракты файлов и транзакций

Страница хранит только непрозрачный дескриптор авторизации, отображаемое имя и объявление возможностей. Хост хранит реальный путь, URI, закладки и флаги авторизации. Каждый хост регистрирует идентичность цели в масштабе всего приложения; подтверждённые псевдонимы пути, идентификаторы файла или идентификаторы документа провайдера должны разделять одну запись занятости.

«Сохранить как» последовательно выполняет выбор цели, атомарное резервирование, сохранение намерения записи, первую запись, проверку результата, сохранение привязки и переключение привязки в памяти. Первая запись использует текущее поколение цели плюс один; старая цель освобождается только после подтверждения новой привязки. Цель, в которую запись прошла успешно, но привязка ещё не завершена, остаётся занятой. При неопределённом результате проверяется только исходная операция, без повторной отправки и без освобождения цели для других сессий.

Когда кандидатная цель уже определённо завершилась ошибкой и больше нет ожидающих подтверждения транзакций, пользователь всё равно может сохранить или повторить запись в исходную цель; ошибка кандидата и его базовая линия не должны применяться к исходной цели. Настольное сохранение POSIX должно подтверждать локальную долговечность после проверки замены и успешной синхронизации родительского каталога; при сбое синхронизации каталога сохраняются неопределённая транзакция и текст восстановления, а повторная проверка лишь дополняет подтверждение без повторной записи текста. Windows использует существующий процесс замены.

Каждая запись привязывается к неизменяемым сессии, поколению цели, версии редактирования и номеру операции. Хост выполняет файловые операции последовательно, проверяя дайджест запроса для повторяющихся номеров; квитанции о завершении используют ограниченный кэш, а устаревшие операции не должны выполняться повторно. При неопределённом результате сохранения обновлённой привязки нельзя подтверждать запоздавший черновик старого поколения как сохранённый; после подтверждения сохранённой новой привязки запоздавший черновик должен быть сопоставлен с новым поколением.

Внешняя перезагрузка отдельно привязывается к версии редактирования и порядковому номеру запроса. Намерение ввода немедленно делает выполняющуюся перезагрузку недействительной, не дожидаясь отложенной генерации снимка Markdown; при наличии ожидающего фиксации ввода автоматическая перезагрузка не запускается. Если во время чтения произошли редактирование, переключение, закрытие или более новый запрос перезагрузки, старый результат не может изменять текст, базовую линию или сохранённую версию. Программная перезагрузка и переключение режима без редактирования не должны вызывать автоматическую запись обратно в файл.

Настольное отслеживание файлов объединяет уведомления файловой системы по цели, а сравнение с принятой версией выполняет текущая сессия; базовая линия сохранения при открытии хостом не может использоваться для фильтрации внешних изменений. Внешние последовательные сохранения, возврат к исходному содержимому и удаление передаются на проверку сессии, а собственные записи и уведомления без изменения содержимого сессией игнорируются.

Файлы только для чтения допускают редактирование копии и «Сохранить как», но не могут отображаться как записанные обратно в исходный файл. При недостаточных правах доступа к файлу предлагается выбрать файл заново или сохранить как копию. Успешное сохранение единообразно отображает «Сохранено в файл»; облачная синхронизация управляется соответствующим облачным диском, и неподтверждённая облачная синхронизация не означает ошибку сохранения файла. Подтверждение сохранения и контракт `durability` остаются неизменными.

## Дерево файлов и переключение в том же контейнере

При открытии `A.md` его каталог используется как корень навигации по умолчанию, отображая реальные каталоги и файлы `.md`, `.markdown`. Каталоги разворачиваются по требованию; каталоги идут первыми, а имена сортируются в естественном порядке без учёта регистра с распознаванием чисел. В левом верхнем углу используется отдельная кнопка панели файлов, показывающая состояние переключения и подсказку; имя файла также может переключать панель: на рабочем столе это боковая панель с изменяемой шириной, на мобильных устройствах — выдвижная панель. Пустые каталоги не показывают строку-заглушку, но сообщения о загрузке и ошибках чтения сохраняются. Если на мобильной платформе однофайловой авторизации недостаточно для перечисления каталога, пользователю предлагается выбрать содержащий каталог; отмена авторизации не влияет на редактирование текущего текста.

При разворачивании и сворачивании каталогов используется такой же переход высоты на 200 мс, как и в панели документов, с функцией плавности `cubic-bezier(0, 0, .2, 1)`; при первой загрузке, фоновом обновлении и включённом в системе уменьшении анимации переход не воспроизводится. Разворачивание сначала ждёт готовности первой порции списка, сохраняя свёрнутый макет во время ожидания; если после запуска каталог снова свернули, переключили корень или закрыли страницу, старый результат не может повторно развернуть каталог. Анимация композитит только смонтированные строки и виртуальное пространство-заглушку, а уходящий снимок неинтерактивен; быстрая обратная операция, прокрутка, изменение макета и заморозка завершают текущий переход, не расширяя область рендеринга больших каталогов.

Щелчок по файлу в дереве переключает документ в текущем контейнере редактирования. Перед запуском чтения кандидата страница сначала получает уже зафиксированный ввод текущего документа и ждёт подтверждения сохранения приватного черновика; при ошибке подтверждения или активном вводе IME чтение не начинается. Общий протокол `tree-prepare-open` читает и занимает целевого кандидата; после подтверждения возможности открытия кандидата страница выполняет защиту выхода для исходного файла: сохранение, удержание черновика, «Сохранить как» или отмену. Если во время чтения кандидата приложение уходит в фон, оно может ответить после подтверждения уровня черновика и постараться сохранить исходный файл, не дожидаясь завершения медленного чтения у провайдера. После освобождения старой сессии `tree-commit-open` выполняет только идемпотентное переключение привязки в памяти; для отмены используется `tree-cancel-open`, освобождающий кандидата. При потере квитанции фиксации можно повторить отправку с тем же билетом или проверить текущую сессию через `bootstrap`. Мобильный мост ждёт подтверждения привязки 5 секунд, а снимка — 30 секунд, после чего сообщает о тайм-ауте; обычная запись файла из-за этого не повторяется. Если не удаётся подтвердить новую привязку, текст остаётся замороженным, разрешается только повтор подтверждения, а уже освобождённая старая сессия редактирования не восстанавливается. Чтение и занятие кандидата участвуют в очистке при выходе и уничтожении контейнера; старая цель с неопределённым результатом записи не освобождается.

Нативный контейнер и источник страницы остаются фиксированными; переключение документа создаёт новую сессию, сохраняя уже подтверждённое на диске содержимое восстановления старой сессии. Мост, отчёты о состоянии, токены изображений и асинхронные результаты старой сессии не могут попадать в новый документ. Переключение внутри дерева сохраняет прежний корень; «Сохранить как» внутри корня также сохраняет его, а при сохранении за пределы корня следует за новым родительским каталогом. «Ещё — Открыть папку» только переопределяет корень навигации, не переключая и не заменяя текст, и не меняет немедленно выбор пользователя, если текущий файл находится вне выбранного корня.

Корень дерева и узлы предоставляют странице только непрозрачные идентификаторы, выданные хостом. Хост хранит реальные пути, URI или закладки, проверяя область авторизации, идентичность файла, ссылки каталогов и циклы; авторизация дерева не включает право чтения изображений или произвольных файлов. Список каталога и регистрация корневых узлов ограничены 10 000 элементами и максимальной глубиной 64; при превышении лимита явно сообщается об ошибке и предлагается выбрать меньший каталог, без молчаливого усечения результата. Состояние развёрнутости сохраняется по стабильным идентификаторам; развёрнутые каталоги обновляются через отслеживание, доступные на платформе уведомления об изменениях или при возврате фокуса. При удалении текущего файла или отзыве прав его выделение снимается, а доступный корневой каталог по-прежнему позволяет переходить к другим файлам. Страница рендерит список по видимому диапазону; после смены корня или поколения каталога старые квитанции списка не могут попадать в новое дерево. Дерево файлов отвечает только за навигацию и не предоставляет переименования, удаления или перетаскивания.

## Возможности и границы платформ

На рабочем столе временный файл записывается в том же каталоге, после чего проверяется исходная цель и выполняется замена; для нового файла используется создание без перезаписи существующей цели. Windows использует системный интерфейс замены, сохраняющий метаданные исходного файла, а POSIX-путь сохраняет права доступа и владельца. Ни дайджест, ни проверка идентичности файла, ни атомарная замена не являются межприложенческим compare-and-swap, поэтому нельзя утверждать, что исключены все внешние конкурентные записи.

Android использует SAF и фактические флаги авторизации, не запрашивая доступ ко всему диску. iOS использует UIDocument и security-scoped bookmark; только реальный completion сохранения означает завершение данной операции записи, а само уведомление об ошибке не является барьером завершения записи. HarmonyOS использует выбор файлов и восстановление авторизации по интерфейсам от API 18 до целевого API 20. Мостовая передача HarmonyOS использует отдельный бюджет кодирования 64 МиБ, не смешиваемый с лимитом исходного файла 8 МиБ; отпечаток запроса вычисляется по фиксированному перед записью закодированному содержимому. Когда провайдер не поддерживает условную запись, используются проверка перед записью, цикл короткой записи, усечение, результат закрытия и проверка после записи с сохранением данных восстановления. При неопределённом результате сохранения или закрытия занятие цели сохраняется.

На iOS и HarmonyOS «Сохранить как» использует выбор каталога плюс имя файла, чтобы средство выбора экспорта или сохранения не записывало текст до резервирования цели приложением. Платформенный провайдер может изменить авторизацию, идентичность или доступность; при ошибке пользователь должен выбрать цель заново, а URI или голый URL не считаются долгосрочной авторизацией.

## Ресурсы и безопасность

Настольное окно отключает интеграцию с Node и включает песочницу и изоляцию контекста. Мост проверяет окно, главный frame, фиксированный источник страницы и сессию. Android использует WebMessageListener, разрешающий только доверенный главный frame; iOS проверяет frame и источник WKScriptMessage; HarmonyOS передаёт главной странице выделенный WebMessagePort и не регистрирует файловый прокси, который может быть напрямую вызван из дочерних frame.

Страница файла напрямую отображает сетевые изображения HTTP и HTTPS, а адреса изображений без указания протокола используют HTTPS; SVG-значки в виде изображений также могут отображаться без выполнения встроенных скриптов. Сетевые изображения не требуют локальной авторизации каталога, не конвертируются и не скачиваются в рабочую область, а загрузка и перенаправления не изменяют исходные ссылки в тексте. Страница не отправляет адрес источника (Referer), а сетевые сбои обрабатываются как ошибки загрузки изображения.

Скрипты, обработчики событий, активный HTML, iframe, встроенный SVG и динамические диаграммы в документах по-прежнему не могут выполняться. CSP страницы разрешает HTTP и HTTPS только для изображений; фильтрация запросов на рабочем столе и правила контента iOS также ограничивают сетевой доступ по типу изображений, Android и HarmonyOS полагаются на CSP для ограничения сетевых подресурсов, а нативный перехват продолжает защищать локальный виртуальный источник. Внешние веб-ссылки и почтовые ссылки должны инициироваться пользователем и открываться хостом после проверки протокола. Необходимые скрипты, стили, шрифты и значки полностью упаковываются вместе со страницей.

Однофайловая авторизация на мобильных платформах не даёт прав на содержащий каталог. Авторизация документа и навигации по дереву файлов не предоставляет неявного права доступа к изображениям; относительные изображения требуют отдельной авторизации каталога или файла, а результатом разрешения является адрес только для чтения, ограниченный сессией. Разрешение и чтение должны проверять область авторизации и идентичность, а недействительный токен не может быть повторно разрешён в другой файл. Сериализация текста восстанавливает исходные ссылки; временные адреса не должны записываться обратно в файл. При вставке изображения сначала выбирается и успешно сохраняется ресурс, затем вставляется ссылка; «Сохранить как» не копирует ресурсы и не изменяет ссылки неявно.

Авторизация каталога изображений на рабочем столе одновременно привязывается к выбранному пользователем пути, каноническому пути и идентификатору каталога; повторная проверка выполняется при разрешении ресурса, фактическом чтении и завершении чтения. Если каталог по тому же пути был заменён, перемещён или символическая ссылка выбранного пути стала указывать на другой объект, старая авторизация и выданные токены становятся недействительными и требуют повторной авторизации.

## Интерфейс, лимиты и планирование

Окно носит название SiYuan; строка заголовка отображает кнопку панели файлов, имя файла, отмену, повтор и кнопку «Ещё». Отдельная панель форматирования в тексте не предусмотрена; отмена и повтор переиспользуют историю текущего режима Vditor и синхронизируют состояние доступности, отключаясь во время ввода IME и заморозки сессии. Действия с файлами, изображениями, авторизацией каталогов, восстановлением и внешним видом находятся в меню «Ещё», где каждый пункт использует соответствующий значок; режим редактирования и внешний вид единообразно используют выпадающие вбок подменю второго уровня, причём в «Внешнем виде» размещены подменю с отметками для темы и размера шрифта; при нехватке места они раскрываются в другую сторону и поддерживают пошаговую клавиатурную навигацию и закрытие. Метки заголовков H1–H6 разделяют фактическую высоту строки с первой строкой заголовка и сохраняют вертикальное выравнивание. Внизу отображается статус сохранения; действия для конфликтов и ошибок появляются только в соответствующих состояниях. Настольное окно переиспользует безрамочную конфигурацию SiYuan: Windows использует нативное наложение кнопок окна, macOS сохраняет системный светофор, Linux предоставляет кнопки окна в строке заголовка; за пустую область строки заголовка можно перетаскивать окно, а закрытие по-прежнему проходит через сохранение и защиту черновиков. Стили переиспользуют элементы управления, меню и переменные тем SiYuan без загрузки среды выполнения меню рабочей области. Закрытие совершенно новой и ни разу не редактировавшейся пустой страницы не вызывает подтверждение сохранения и не создаёт пустую запись восстановления; очистка после фактического редактирования, изначально непустая копия и восстановленный черновик по-прежнему защищаются при выходе.

Оболочка Vditor, текст и тема подсветки кода настраиваются раздельно: при инициализации и переключении необходимо синхронизировать все три, используя для тёмной темы `dark` для текста и `github-dark` для подсветки, а для светлой — `light` для текста и `github` для подсветки. Настройка только темы оболочки не должна оставлять светлый текст по умолчанию. Все три режима редактирования соблюдают явные настройки внешнего вида и правило следования системе; переключение темы не должно вызывать запись в файл.

Высота настольной строки заголовка составляет 32 px, обычная высота нижней панели — 24 px; кнопки конфликтов и ошибок могут разворачиваться по содержимому. На сенсорных экранах строка заголовка имеет высоту 48 px с областью нажатия кнопок не менее 44 px; видимый фон кнопок со значками сжат до 32 px, значок и фон центрированы, а нативный тактильный отклик не перекрывает внешнюю прозрачную область нажатия. Нативное наложение кнопок Windows синхронизируется с фактической высотой строки заголовка и масштабом страницы. Инструменты разработчика используют те же сочетания клавиш и правила закрепления, что и SiYuan: `Ctrl+Shift+I` в Windows и Linux, `Cmd+Alt+I` в macOS; автоповтор клавиш не вызывает переключение, а отдельная кнопка в интерфейсе не добавляется. Распознавание и переключение сочетаний клавиш внедряются слоем запуска, поэтому автономный модуль Markdown не зависит напрямую от модуля окна рабочей области.

Потеря и получение фокуса в дереве файлов обновляют только стиль фокуса существующих строк без пересоздания строки, на которую нажали мышью, чтобы не терялся первый клик. Переключение файлов в Electron сохраняет старый кадр через снимок представления и меняет картинку после готовности первого предпросмотра исходного кода и первого уровня каталога нового редактора, отключая стандартное затухание; WebView без поддержки View Transition используют прямой путь замены. При переключении режима сразу создаётся базовая линия отмены для этого режима, чтобы можно было отменить даже первую последующую правку.

Лимит чтения и записи исходного файла составляет **8 МиБ**, считая по итоговым байтам UTF-8, включая BOM и преобразование переводов строк; порог для WYSIWYG и предпросмотра задан отдельно на уровне **256 КиБ**. Более крупные файлы открываются напрямую в текстовом поле исходного кода с отключённым предпросмотром всего текста, продолжая поддерживать редактирование, автосохранение, «Сохранить как», обнаружение конфликтов и восстановление. При вводе и вставке в исходном коде предпросмотр большого содержимого отключается до обработки целевого события; крупная вставка в WYSIWYG сначала переключается в исходный код, а затем вставляется; обычное редактирование при пересечении порога также переводится в исходный код. Внешняя перезагрузка сначала определяет режим, а затем устанавливает текст, чтобы избежать предварительного рендеринга большого содержимого; после сокращения текста ниже порога можно снова выбрать режим WYSIWYG. Автоматическое понижение режима меняет только фактический режим текущего документа и не записывается в общие предпочтения редактирования; при переключении на меньший документ используется предпочтение пользователя, а запоминается только осознанно выбранный режим. Отметка в меню отражает текущий фактический режим, а изменение темы и размера шрифта не должно заменять пониженное состояние на предпочтительный режим. Приватный текст восстановления имеет отдельный бюджет **16 МиБ**; черновик восстановления, превышающий файловый бюджет, всё ещё можно скопировать или сократить, а записать обратно в файл можно только после снижения ниже файлового бюджета. При превышении файлового бюджета исходный файл сохраняется и явно сообщается об ошибке.

Задержка снимка undo/input в Vditor составляет 250 мс; слой адаптера уведомляет сессию через 300 мс после последнего ввода, переиспользуя уже сгенерированное Vditor содержимое, а при непрерывном вводе ждёт не более 1000 мс для фиксации завершённого снимка редактирования. Задержка автосохранения после уведомления сессии составляет 250 мс; при входе в ввод IME или получении нового намерения ввода ожидающее сохранение отменяется. Закрытие, ручное сохранение и «Сохранить как» напрямую забирают последнее зафиксированное содержимое. Намерение ввода немедленно выводит интерфейс из состояния «Сохранено», а версия черновика по-прежнему подтверждается только после реальной записи на диск.

После завершения намерения ввода, отклонения сверхлимитного ввода или снятия заморозки после отмены файловой операции автосохранение перепланируется согласно текущей версии изменений и состоянию доступности для записи; действия, не меняющие текст (например, нажатие горячей клавиши повтора при отсутствии истории), также не должны навсегда отменять сохранение уже сделанных правок. Когда мобильная выдвижная панель файлов раскрыта, текст под маской и панель восстановления переводятся в состояние `inert`; после закрытия восстанавливается состояние согласно заморозке.

Накладные расходы на преобразование WYSIWYG, снимки отмены и полную сериализацию растут с плотностью синтаксиса, поэтому для WYSIWYG и предпросмотра используется отдельный от размера файла порог. Файловый бюджет 8 МиБ ограничивает полные копии текста для исходного кода, моста, хеширования и сохранения на диск, а бюджет восстановления оставляет для него запас. Порог 256 КиБ учитывает типичные руководства, документацию и накладные расходы полного преобразования WYSIWYG, однако плотные блоки кода или таблицы в пределах порога всё равно могут вызывать подтормаживания — порог не гарантирует плавность для любого синтаксиса. Изменение диапазона WYSIWYG требует одновременной оценки парсинга, отмены, сериализации и записи черновиков.
