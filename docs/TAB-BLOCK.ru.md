# Блок вкладок

[English](TAB-BLOCK.md)

Связанная задача: https://github.com/siyuan-note/siyuan/issues/17642

## Область функциональности

Блок вкладок размещает несколько групп содержимого в одном контейнере, позволяя переключать их отображение через навигацию по заголовкам сверху или слева. Каждый элемент вкладки является контейнером с собственным ID блока и может содержать обычные блоки и вложенные блоки вкладок.

## Взаимодействие с пользователем

### Меню и редактирование

Значок блока управляет всем блоком вкладок целиком. Меню значка блока — «Блок вкладок» содержит «Вкладки сверху», «Вкладки слева» и после разделителя «Задача»; отметки выбора для всех трёх пунктов расположены справа. Эти пункты и разделитель зарегистрированы в настраиваемом каталоге меню и поддерживают настройку видимости и порядка.

Контекстное меню заголовка действует на текущую вкладку, предлагая копирование ссылки на блок, а в режиме записи — переименование, создание копии и удаление; для вкладок-задач дополнительно доступно «Пользовательский статус задачи». На панели заголовков нет отдельной кнопки «Ещё». Входы для преобразования всей группы находятся в меню значка блока — «Преобразовать в», включая маркированный список, нумерованный список, список задач и суперблок.

Одиночный щелчок по заголовку переключает вкладку, а двойной щелчок или выбор «Переименовать» редактирует форматированный текст прямо на месте заголовка, переиспользуя обработку строчного форматирования, выделения и IME из заголовка блока-выноски. Копия заголовка в навигации отвечает только за отображение; сохранение и обратный разбор опираются на исходный заголовок внутри элемента вкладки. Стили вроде цвета шрифта принадлежат содержимому заголовка, поэтому при переименовании он не преобразуется предварительно в строку кода для редактирования пользователем. Завершение редактирования сохраняет позицию прокрутки панели вкладок и скрывает строчную панель инструментов; скрытое выделение заголовка не должно вызывать панель инструментов в верхней части документа.

Новый блок вкладок по умолчанию содержит две вкладки, каждая с одним пустым абзацем. Новая вкладка добавляется в конец группы, выбирается и переходит в режим редактирования заголовка. Длинные заголовки в навигации обрезаются с многоточием по ширине, а при наведении отображается подсказка с заголовком; полный текст не усекается до фиксированного числа символов. Навигация и кнопка добавления не могут быть выделены как обычный текст.

#### Статус задачи

После установки `tabs-task="true"` на блоке вкладок все его прямые элементы вкладок отображают статус задачи; вкладки без собственного статуса по умолчанию считаются невыполненными. Значение `tabs-task` элемента вкладки, равное одному пробелу ASCII, означает «не выполнено», `X` или `x` отображают значок выполнения, а остальные поддерживаемые односимвольные статусы отображаются как исходный символ, переиспользуя рамку значка невыполненной задачи. Ввод пользовательского статуса использует проверку маркера списка задач: принимается один символ ASCII, кроме квадратных скобок. Статус независим от заголовка и выбранной вкладки, записывается в документ и синхронизируется.

Пункт «Задача» в меню значка блока является переключателем всей группы: он отображается отмеченным, если на уровне группы задано `tabs-task="true"` или у любого прямого элемента есть `tabs-task`; при выключении удаляются атрибуты задачи уровня группы и всех прямых элементов, при включении устанавливается атрибут уровня группы, а все прямые элементы по умолчанию становятся невыполненными. Если в группе есть элементы-задачи, новая вкладка также создаётся как невыполненная задача. При переносе между группами вкладка сохраняет собственный статус, а обычная вкладка при переносе в группу задач по умолчанию становится невыполненной. Старые документы без атрибута уровня группы по-прежнему поддерживают смешанные группы, а переключатель группы позволяет обработать их единообразно.

Щелчок по значку статуса не переключает вкладку и не запускает переименование: «к выполнению» и «в работе» переходят в «выполнено» (`X`), а остальные статусы переходят в «к выполнению» (пробел). Правый щелчок по значку, как и по заголовку, открывает полное меню текущего элемента вкладки, в режиме записи напрямую перечисляя «К выполнению», «В работе», «Выполнено», «Отменено» и «Пользовательский статус задачи», отделённые от остальных действий разделителем, без вложенного подменю «Статус задачи». В режиме только для чтения меню по-прежнему открывается для копирования ссылки на блок. Для «в работе» используется `/`, для «отменено» — `-`; заголовок отменённой вкладки в навигации приглушается и перечёркивается, а «в работе» отображается обычно. Значок статуса не показывает отдельную всплывающую подсказку «Список задач».

Правый щелчок по значку списка задач открывает полное меню блока элемента списка. Меню значка блока — «Блок списка» напрямую перечисляет пять вариантов статуса, оставляя только один пункт пользовательского статуса, с разделителем между группой статусов и операциями вставки списка. Конфигурация меню версии 6 разворачивает старое подменю статусов на прежнее место, сохраняя порядок подпунктов и позиции плагинов; видимость двух прежних пользовательских пунктов объединяется: если хотя бы один из них был видим, новый пункт остаётся видимым. Значок задачи отображает исходный пользовательский символ, текст «в работе» отображается обычно, текст «отменено» приглушается и перечёркивается, а «выполнено» сохраняет прежний стиль. Отображение основывается на исходном маркере, а правило совместимости хранения для непустых отмеченных значений не меняется; экспорт в Markdown по-прежнему следует существующим правилам нормализации маркеров задач. Установка и переключение по щелчку поддерживают отмену и повтор. При отдельном копировании, вырезании или перетаскивании элемента вкладки унаследованный невыполненный статус записывается в целевой элемент, чтобы при выходе из группы задач он не превращался в обычную вкладку; после отмены перемещения восстанавливается прежний унаследованный атрибут.

#### Преобразование в список и суперблок

Преобразование списка во вкладки затрагивает только текущий уровень. Первый абзац каждого прямого элемента списка становится заголовком с сохранением всего текста, строчного форматирования, ссылок, ID и атрибутов, без дублирования в основном тексте. Если первый блок не является абзацем, используется пустой заголовок, а исходный блок остаётся в основном тексте. Подсписки и вложенные вкладки не разворачиваются; после преобразования выбирается первая вкладка.

При обратном преобразовании в список отдельный абзац заголовка переносится обратно в начало с удалением `tabs-title`, а основной текст следует за ним; непустой строковый заголовок порождает новый абзац. Даже если текст заголовка и основного текста совпадает, дедупликация не выполняется. Элемент списка, содержавший только заголовок, при преобразовании во вкладку создаёт точку опоры основного текста, а при обратном преобразовании опускается только тот абзац `tabs-placeholder`, который остался пустым и не имеет строчных элементов, пользовательских атрибутов или счётчика ссылок.

Преобразование списка задач во вкладки сохраняет статусы «не выполнено», «выполнено» и пользовательские статусы; при преобразовании обратно в список задач восстанавливается текущий `tabs-task`, а элементы без атрибута задачи по умолчанию считаются невыполненными. Преобразование в обычный список удаляет атрибуты задачи. Нумерованный список нумеруется заново с 1; макет и состояние выбора не сохраняются как резервная копия для обратного преобразования.

Преобразование в суперблок превращает контейнер вкладок и каждый элемент вкладки в вертикальный суперблок, заголовки становятся абзацами, а исходные ID контейнера, элементов вкладок и основного текста сохраняются. Преобразования в список и суперблок поддерживают отмену через обычную транзакцию редактирования.

### Выбор, позиционирование и перетаскивание

Активное переключение в редактируемом редакторе, а также переключение при поиске и переходе по ссылке на блок сохраняют `tabs-active-id` через интерфейс атрибутов, ставясь в очередь после транзакции редактирования. Переключение вкладки не занимает стек отмены основного текста и не обновляет время изменения основного текста, но сохраняется на диск и синхронизируется. Страницы только для чтения, встроенный предпросмотр, предпросмотр истории и экспорт HTML могут временно переключать вкладки без записи выбора обратно.

При восстановлении позиции после обновления или перезапуска сохранённый выбор вкладки имеет приоритет над старым курсором на скрытой вкладке; фокус переносится в основной текст текущей вкладки без переиспользования устаревшего текстового смещения. При активном переходе к скрытому содержимому соответствующие вкладки активируются поуровнево. Если внешнее обновление выделения должно скрыть редактируемый в данный момент основной текст, переключение интерфейса откладывается, чтобы не прерывать фокус и ввод IME.

Элементы вкладок используют обычный синтаксис ссылки на блок, например `((20260905120000-item001 'Заголовок вкладки'))`, без введения специального синтаксиса ссылок. Целью ссылки является ID элемента вкладки, и при переходе активируется соответствующая вкладка; всплывающий предпросмотр ссылки дополняет отсутствующий родительский контейнер вкладок для корректного рендеринга. Ссылки и ресурсы строкового заголовка принадлежат элементу вкладки, а ссылки и ресурсы отдельного абзаца заголовка принадлежат исходному ID этого абзаца.

Перетаскивание заголовка навигации перемещает всю вкладку, а перетаскивание блока основного текста перемещает содержимое. Предпросмотр сортировки раздвигает соседние кнопки, приглушает перетаскиваемую кнопку и автоматически прокручивает края навигации; горизонтальный и вертикальный макеты используют соответствующее направление. После отпускания фиксируется одна транзакция; отмена или возврат на прежнее место транзакцию не фиксируют. Межгрупповое перемещение корректирует состояние обеих групп в одной транзакции; цели только для чтения и собственные потомки не принимают сброс.

Удаление текущей вкладки сначала выбирает следующую вкладку, иначе предыдущую; удаление последней вкладки превращает блок в пустой абзац. Обычное выделение текста не включает скрытый основной текст, а копирование и удаление всего блока целиком охватывают все вкладки. Backspace и Delete на границе основного текста не объединяют автоматически соседние вкладки.

## Данные и хранение

### Модель данных

| Узел или атрибут | Значение |
| --- | --- |
| `NodeTabs` | Контейнер вкладок; прямыми дочерними блоками являются `NodeTabItem` |
| `NodeTabItem` | Элемент вкладки; содержит заголовок и основной текст, не может напрямую вмещать документ, голый элемент списка или голый элемент вкладки |
| `TabItemTitle` | Строчный Markdown-заголовок в виде строки; представление строчного содержимого переиспользует блок-выноску |
| `tabs-title="true"` | Помечает первый `NodeParagraph` элемента вкладки как отдельный блок заголовка; при наличии этот абзац является единственным источником заголовка, а `TabItemTitle` больше не используется |
| `tabs-active-id` | ID выбранного прямого элемента вкладки, хранящийся в IAL контейнера; при отсутствии или недействительности откатывается к первой вкладке |
| `tabs-position` | Макет, хранящийся в IAL контейнера; принимает значения `top` или `left`, по умолчанию `top` |
| `tabs-task` | Значение `true` в IAL блока вкладок включает задачи для всей группы; в IAL элемента вкладки хранит символ статуса, при отсутствии наследует статус невыполненной задачи группы, иначе является обычной вкладкой |
| `tabs-placeholder="true"` | Помечает пустой абзац основного текста, автоматически созданный при преобразовании списка во вкладки |

Порядок вкладок определяется порядком дочерних узлов. Заголовки допускают повторение и очистку; текст-заглушка пустого заголовка в интерфейсе не записывается в содержимое. Отдельный абзац заголовка сохраняет собственный ID, атрибуты блока и полное строчное содержимое.

Корректные данные содержат не менее одного элемента вкладки и не менее одного блока основного текста на каждой вкладке; для пустого основного текста используется пустой абзац. Функция `NormalizeTabs` в ядре дополняет отсутствующие пустые контейнеры и пустой основной текст, а также исправляет выбранный элемент и недопустимые атрибуты макета. При удалении или переносе последней вкладки на фронтенде исходный контейнер вкладок преобразуется в пустой абзац с сохранением ID контейнера.

Перемещение сохраняет ID. При пересоздании ID во время копирования, вставки шаблона, импорта и восстановления синхронно переназначаются `tabs-active-id`, а также внутренние ссылки на блоки и блочные ссылки в заголовках, тогда как внешние ссылки сохраняют прежние цели. Отдельный элемент вкладки является допустимым фрагментом редактирования и при вставке в обычный текст создаёт контейнер вкладок; при прохождении фрагмента через внутреннее преобразование Markdown используется временная обёртка с восстановлением по идентичности фрагмента.

### Синтаксис Markdown

```markdown
::: tabs
@tab **Windows**

Инструкция для Windows.

@tab:active Linux

Инструкция для Linux.
:::
```

Открывающее ограждение содержит не менее трёх двоеточий, между двоеточиями и `tabs` требуется пробел или табуляция, канонический вывод использует один пробел. `@tab` или `@tab:active` начинает прямой элемент вкладки; при наличии заголовка маркер и строчный заголовок разделяются пробелом или табуляцией. У элемента вкладки нет отдельного закрывающего маркера, а вся группа закрывается отдельной строкой с ограждением из двоеточий той же длины, что и открывающее ограждение.

Первый допустимый `@tab:active` в группе задаёт выбранный элемент, имея приоритет над `tabs-active-id` в IAL группы. При отсутствии этого маркера сохраняется допустимый атрибут, иначе происходит откат к первой вкладке. Внутренний Markdown выводит выбранный элемент как `@tab:active`; вложенные группы обрабатываются независимо.

Вкладки могут вкладываться в списки, цитаты, суперблоки и другие элементы вкладок. Внешнее ограждение должно быть длиннее содержащихся в нём внутренних ограждений; отступы опциональны. Канонический вывод вычисляет длину ограждения по глубине вложенности без дополнительного отступа основного текста: три двоеточия для одного уровня, четыре снаружи и три внутри для двух уровней; фиксированного предела глубины вложенности в синтаксисе нет.

```markdown
:::: tabs
@tab Первая вкладка внешнего уровня

::: tabs
@tab Первая вкладка внутреннего уровня

Внутренний текст.
:::

@tab Вторая вкладка внешнего уровня

Внешний текст.
::::
```

Маркеры внутри блоков кода сохраняются буквально. Буквальный маркер вкладки в начале строки основного текста экранируется как `\@tab` или `\@tab:active`. Изолированный `@tab` вне группы является обычным текстом; текст до первого маркера сохраняется во вкладке с пустым заголовком. Незавершённый ввод закрывается в пределах области разбора, а канонический вывод дописывает отсутствующее закрывающее ограждение. Старые `:::tabs` и `:::tab` не распознаются как синтаксис вкладок, однако существующая структура узлов `.sy` не затрагивается.

IAL элемента вкладки располагается на следующей строке после маркера заголовка без пустой строки между ними, после чего отделяется пустой строкой от основного текста. IAL группы следует за закрывающим ограждением, а IAL блока основного текста — непосредственно за соответствующим блоком. Статус задачи также использует IAL элемента вкладки:

```markdown
::: tabs
@tab:active Пример задачи
{: id="20260905120000-item001" tabs-task="/"}

Основной текст.
{: id="20260905120000-para001"}
:::
{: id="20260905120000-tabs001" tabs-active-id="20260905120000-item001" tabs-position="left"}
```

Отдельный абзац заголовка во внутреннем Markdown выводится как первый абзац с сохранением `tabs-title="true"`, ID и атрибутов; при этом строка `@tab` не дублирует текст заголовка. Структурированный Markdown буфера обмена, напротив, записывает полный заголовок в строку `@tab`, не дублируя абзац заголовка.

## Реализация и интерфейсы

### Рендеринг и макет

`NodeTabs` соответствует `.tabs`, а прямые элементы — `.tab-item`; навигация находится в `.tabs-header.protyle-action` без ID блока содержимого. Исходный заголовок находится в `.tab-item-title.callout-title` внутри `.tab-item-info`, а основной текст — в `.tab-item-content`, без переиспользования класса основного текста блока-выноски. При редактировании заголовка `.tabs-title-editor` накладывается поверх соответствующей кнопки навигации.

Контейнер использует границы и скругления темы. Верхняя навигация может прокручиваться горизонтально; левая навигация распределяет ширину по содержимому с минимальной шириной 80px и верхним пределом, равным меньшему из 200px и 40% ширины контейнера, оставляя со стороны основного текста интервал 48px для операций значка блока. При ширине контейнера менее 420px временно отображается верхняя навигация без перезаписи `tabs-position`.

Навигация предоставляет семантику `tablist`, `tab`, `tabpanel`; каждый экземпляр рендеринга использует уникальные идентификаторы DOM. Клавиши со стрелками, Home и End перемещают фокус навигации, а Enter или пробел активируют вкладку; при редактировании заголовка действуют правила редактирования текста. Скрытые вкладки продолжают получать обновления данных, а при отображении заново обрабатывают зависящие от размера узлы рендеринга и базы данных.

### Индексирование и экспорт

Заголовки участвуют в полнотекстовом индексе, сканировании ссылок и ресурсов, динамическом тексте якорей и сравнении истории. Строковые заголовки обрабатываются через временное строчное дерево, а отдельные абзацы заголовков — как обычные абзацы во избежание повторного сканирования. Именование блока имеет приоритет над заголовком в качестве текста якоря ссылки. Заголовки внутри вкладок не участвуют в нумерации заголовков документа, а сворачивание не пересекает границы элементов вкладок.

Внутренний Markdown сохраняет полную структуру и атрибуты. Структурированный вывод при включённом `TabsMarkdown` сохраняет ограждения, полный строчный заголовок, маркер выбора и IAL статуса задачи; буфер обмена не выводит полные IAL блоков, такие как ID блоков. Плоский вывод при отключении этой опции последовательно выводит заголовок и основной текст каждой вкладки. Обычное копирование выделенного текста удаляет навигацию, скрытый основной текст и обёртку контейнера вкладок.

HTML отображает всё содержимое до инициализации и скрывает невыбранные вкладки только после успешной инициализации интерактивности. Печать, PDF и Word разворачивают все вкладки, включая вложенное содержимое.

## Совместимость и восстановление

Документы, содержащие узлы вкладок, используют `Spec 3`, обычные документы — `Spec 2`; обновлённые документы не понижаются автоматически. Точка входа чтения JSON отклоняет неподдерживаемые будущие версии до парсинга и исправления. Точки входа импорта в старых клиентах, обходящие проверку версии, не обладают такой защитой и не могут использоваться для обработки документов нового формата. Узлы и синтаксис предоставляются Lute, поэтому скрипты генерации фронтенда и зависимости ядра должны включать соответствующую функциональность; фактическая версия зависимости в репозитории определяется по `kernel/go.mod`.

## Область проверки

Проверяются нормализация пустых контейнеров, round-trip преобразование строкового заголовка и отдельного абзаца заголовка, исправление выбранного элемента, переназначение ID при копировании и импорте, а также ограждения Markdown различной глубины вложенности. Для редактирования проверяются форматирование заголовка, ввод IME, статус задачи, преобразования списка и суперблока, отмена, удаление последней вкладки и межгрупповое перетаскивание. Для интерфейса проверяются верхний и левый макеты, откат на узком контейнере, клавиатурная навигация, временное переключение в режиме только для чтения и обновление скрытых вкладок. Для экспорта проверяются структурированный и плоский Markdown, вывод всех вкладок при печати, сканирование ресурсов в заголовках и отклонение неподдерживаемых версий документов.
