# Загрузка файлов ресурсов по требованию

[English](ASSET-DOWNLOAD.md)

Связанное требование: https://github.com/siyuan-note/siyuan/issues/19149

## Область функциональности

`sync.assetDownloadMode` — это настройка устройства: `0` означает полную загрузку, `1` — загрузку по требованию; значение по умолчанию — `0`. Настольная и мобильная версии используют общие настройки и реализацию ядра; функция применима к официальному облаку, S3, WebDAV и синхронизации с локальной файловой системой.

Режим по требованию всегда синхронизирует полные метаданные файлов, а также не являющееся ресурсами содержимое: документы, базы данных, конфигурации, ключи и т. д. Файлы `ocr-texts.json`, аннотации PDF `.sya` и скрытые вспомогательные файлы в каталоге ресурсов также синхронизируются полностью. Стратегии автоматической очистки уже загруженных ресурсов нет; поэтому включение режима по требованию на устройстве с уже имеющимися полными данными не уменьшит немедленно занятое место на диске.

## Взаимодействие с пользователем

При первом обращении к незагруженному ресурсу сначала переиспользуются фрагменты, уже имеющиеся в локальном репозитории, а затем по требованию загружаются недостающие фрагменты. После успешной загрузки этот ресурс продолжает обновляться при последующей синхронизации. Уже имеющееся локальное содержимое не зависит от подключения к сети, входа в учётную запись или переключателя синхронизации. Когда требуется обращение к облаку, используются учётная запись и права сервиса синхронизации данных.

## Данные и хранение

`dejavu` сохраняет в `conf/asset-downloads.json` рабочей области состояние устройства, прошедшее аутентифицированное шифрование ключом репозитория; оно содержит явную версию, идентификатор источника, полные версии файлов незагруженных ресурсов и журнал восстановления незавершённых операций применения. Состояние не участвует в синхронизации данных. Маркер `asset-downloads-v1` в репозитории служит для обнаружения пропуска конфигурации или потери состояния текущей реализацией; при потере состояния, неизвестной версии или ошибке аутентификации возвращается ошибка и сохраняются исходные материалы.

Незагруженные ресурсы по-прежнему входят в логический список файлов текущих данных и снимков. Индекс не должен трактовать их локальное отсутствие как удаление, а синхронизация не может выгружать старые версии ещё не загруженных фрагментов. Уже материализованные файлы продолжают отслеживаться обычным индексом; точки входа удаления, переименования и перемещения ресурсов сначала загружают недостающее содержимое, а затем выполняют прежнюю файловую операцию.

При изменении правил игнорирования синхронизации сначала загружаются вновь игнорируемые незагруженные ресурсы, затем отслеживание прекращается с сохранением локального содержимого и исторических фрагментов; при невозможности получить содержимое сохраняется прежнее состояние и выводится ошибка. Режим только выгрузки загружает только фрагменты, необходимые для фактических кандидатов на выгрузку, не материализуя в рабочей области неиспользуемые ресурсы.

Слияние при синхронизации использует восстанавливаемый журнал применения, фиксирующий целевой список ресурсов, версию до изменения и облачную базовую линию. Перед применением проверяется, соответствует ли локальный файл ожиданиям, с сохранением дополнительных локальных правок, сделанных во время загрузки. Восстановление может быть инициировано только процессом синхронизации явно; создание экземпляра репозитория и чтение ресурсов не должны попутно изменять документы. После обновления файлов и ссылок отдельно сохраняется запись ожидающего подтверждения изменения до тех пор, пока ядро не завершит обновление кэша, индекса и интерфейса; при сбое на полпути уже записанная на диск часть обрабатывается по фактическому состоянию диска, чтобы повтор не пропустил эти изменения. Запись ожидания подтверждения является опциональным полем в первой версии состояния устройства: существующие аутентифицированные состояния и журналы применения без этого поля по-прежнему читаются и восстанавливаются без изменения формата шифрования. Переключение источника и материализация ресурсов сериализуются; внутренние операции репозитория разделяют прежний мьютекс и повторно считывают аутентифицированное состояние устройства, чтобы старый экземпляр не перезаписал новое состояние.

Чтение по требованию и заполнение исторических фрагментов отправляют отчёт о фактически произошедшем облачном трафике загрузки и количестве запросов (пакетное заполнение объединяется в один отчёт); переиспользование локальных фрагментов и загрузка по локальной сети в облачный трафик не включаются, а повторное чтение не отправляет дублирующий отчёт.

## Реализация и интерфейсы

### Чтение и экспорт

Внутреннее разрешение логических путей, поиск ресурсов, проверка отсутствия и запрос размера файла читают только логические метаданные и не запускают загрузку. Недостающее содержимое загружается только при фактическом отображении изображения, воспроизведении аудио/видео, открытии PDF, переходе по ссылке на ресурс, копировании ресурса или экспорте. `/api/asset/resolveAssetPath`, используемый для подготовки реального пути файла при внешнем открытии, также сначала загружает ресурс. HTTP и raw-API файлов сначала выполняют проверку пути, символических ссылок, прав публикации и прав зашифрованного блокнота, а затем выполняют загрузку.

Экспорт предварительно загружает упомянутые ресурсы до захвата блокировки чтения блокнота и создания артефакта, считывая их по фактическому блокноту и полному пути каждого документа; область охватывает дочерние документы, связанные документы, сноски, встроенные запросы, обложки, базы данных и связанные базы данных. На ресурсы сносок при экспорте одного файла не влияет то, экспортируются ли отдельно связанные документы. Ресурсы каталогов загружаются по логическому списку, а не только обходом диска. Ошибки загрузки или копирования распространяются вверх, не сообщая об успехе для артефакта с отсутствующими ресурсами.

Зашифрованные ресурсы после загрузки сохраняют исходный шифротекст, а чтение и экспорт продолжают обрабатываться существующим процессом аутентифицированной расшифровки с сохранением совместимости с выпущенными форматами ресурсов. Конверт ключа, мастер-соль, AAD и вывод ключей не меняются, а ошибки аутентификации не обрабатываются откатом к открытому тексту. Перед чтением и экспортом в открытом виде проверяется допуск к блокноту, без ожидания сети во время удержания блокировки чтения блокнота. Запросы чтения ресурсов и простое перечисление имён файлов для заблокированного блокнота не запускают загрузку; однако полная синхронизация, резервное копирование шифротекста и сохранение истории перед удалением могут загружать исходный шифротекст.

## Совместимость и восстановление

Локальные снимки на устройстве с загрузкой по требованию могут содержать только часть содержимого ресурсов; интерфейс отдельно подсказывает об этом через `requiresDownload`. Чтение исторических ресурсов заполняет фрагменты по точной версии файла этого снимка, не перезаписывая текущие ресурсы рабочей области. Полная загрузка облачного снимка проверяет фрагменты всех целевых файлов, не пропуская проверку даже при наличии метаданных; при сбое метка успеха не создаётся.

Перед восстановлением снимка сначала загружаются ресурсы, необходимые текущей рабочей области и целевому снимку. При переключении обратно на полную загрузку одновременно загружаются текущие ресурсы и недостающее историческое содержимое всех сохранённых снимков; при сбое сохраняется прежняя настройка. Перед сменой источника синхронизации, очисткой облака, удалением текущего облачного каталога и сбросом репозитория или ключа проверяются эти зависимости, и при незавершённости сохраняется прежний источник. Перед пересозданием репозитория состояние устройства и маркер могут быть очищены только при успешной аутентификации старого состояния и полноте зависимостей.

Выход из официального облака позволяет сохранить прежний идентификатор источника, чтобы локальный индекс и уже загруженные снимки продолжали работать при последующей повторной аутентификации той же учётной записи. При наличии незавершённых зависимостей вход в другом регионе, смена учётной записи и удаление учётной записи защищены проверкой целостности.

Не полностью загруженные исторические снимки по-прежнему зависят от сохранности соответствующего облачного содержимого. Очистка облака другими устройствами или внешнее удаление облачных объектов могут сделать исторические версии недоступными для загрузки, поэтому частичный локальный снимок не эквивалентен полной офлайн-резервной копии. Если требуется офлайн-резервная копия или смена источника, необходимо сначала завершить полную загрузку. Старые версии клиентов не знают о маркере состояния устройства, поэтому перед понижением версии также необходимо завершить полную загрузку; маркер не может помешать старой версии принять незагруженные файлы за локально удалённые.

## Область проверки

Реализация затрагивает одновременно `siyuan`, `dejavu` и `petal`. Ядро вызывает новые интерфейсы загрузки ресурсов и целостности снимков `dejavu`, поэтому при выпуске необходимо сначала опубликовать зависимость и обновить версию модуля. При локальной разработке можно использовать временный `replace` на локальную копию `dejavu`, но этот `replace` нельзя коммитить.

Регрессия охватывает взаимную синхронизацию полных устройств и устройств с загрузкой по требованию, одностороннюю синхронизацию, повторную индексацию, обновление удалённой версии, конкурентную материализацию, защиту локальных правок, восстановление после прерывания приложения, ошибку аутентификации состояния, смену источника, заполнение исторических снимков, экспорт ресурсов каталога и существующие форматы зашифрованных ресурсов. На фронтенде выполняется `pnpm run lint`, для языков — `python scripts/check-lang-keys.py`; проверка не выполняется путём сборки фронтенд-артефактов или компиляции и запуска ядра.
