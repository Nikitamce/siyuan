# Менеджер навыков

[English](SKILL-MANAGER.md)

Откройте «Навыки рабочей области» в разделе «Настройки — ИИ — Навыки», чтобы управлять навыками в `data/storage/ai/agent/skills/<каталог>/SKILL.md` текущей рабочей области. Внешние навыки из `~/.agents/skills` остаются в соседнем списке только для чтения, и их можно включать по отдельности.

## Управление файлами

Выполните поиск по списку файлов и выберите `SKILL.md` или сопутствующий текстовый файл навыка для редактирования, включая JSON, YAML, скрипты и файлы без расширения. Возможность редактирования определяется по содержимому, а не по расширению: файл должен быть в корректной кодировке UTF-8, размером не более 8 МиБ и не содержать управляющих символов, кроме табуляции, перевода строки, возврата каретки и перевода страницы. Скрипты редактируются только как текст — менеджер их не выполняет. При сохранении содержимое записывается напрямую по выбранному пути без преобразования в документ SiYuan и без перегенерации YAML frontmatter. Редактор сохраняет UTF-8 BOM и единый формат переводов строк LF, CRLF или CR; после редактирования файла со смешанными переводами строк они унифицируются до LF. Если файл не изменён или изменения отменены, сохраняется исходный текст. Перед отказом от несохранённых изменений требуется подтверждение. При замене существующего файла сохраняются его биты прав доступа, включая право на выполнение для скриптов.

Создание нового навыка создаёт каталог с файлом `SKILL.md`. Внутри навыка можно создавать новые текстовые файлы и папки, переименовывать редактируемые файлы или папки в пределах текущего родительского каталога и удалять редактируемые файлы или папки. При создании нового файла используется введённое имя без автоматического добавления расширения. Поддерживаются допустимые имена вроде `.config.json` и `.claude/`. Файл `SKILL.md` в корневом каталоге навыка нельзя переименовать или удалить отдельно; чтобы удалить навык, необходимо удалить весь каталог навыка. Переименование каталога навыка не изменяет отдельное поле `name` во frontmatter.

Двоичные файлы, файлы с неподдерживаемой кодировкой и файлы размером более 8 МиБ отображаются в списке, но их нельзя отдельно редактировать, переименовывать или удалять в интерфейсе управления. При выборе файла указывается причина невозможности редактирования; в локальной настольной версии можно также открыть расположение файла для управления через другие приложения. Удаление папки также удаляет всё её содержимое, включая файлы, которые нельзя редактировать в интерфейсе управления, и не может быть отменено через менеджер навыков.

В мобильной версии менеджер навыков отображается через полноэкранную подстраницу настроек. После выбора файла открывается страница редактирования с кнопками «Назад» и «Сохранить» вверху. При возврате к списку файлов сохраняется позиция прокрутки, а при возврате в настройки — прежнее состояние страницы настроек. Подтверждение несохранённых изменений и адаптация к экранной клавиатуре сохраняются; для кратких подтверждений и ввода имени используются обычные диалоги.

## Идентификация файлов и конкурентные изменения

Операции определяют файлы по пути относительно каталога навыков рабочей области. Поле `name` во frontmatter не служит идентификатором файла: имя может отличаться от имени каталога, а совпадение имён не скрывает файлы в списке управления. Существующие правила обнаружения и приоритета навыков остаются неизменными.

При чтении файла или папки возвращается номер ревизии. При обновлении, переименовании или удалении существующего элемента необходимо передать этот номер ревизии; если элемент уже изменился, операция отклоняется. При конфликте текущее содержимое на диске остаётся неизменным; сохраните черновик редактирования, перезагрузите элемент и затем решите, как объединить изменения. Интерфейс управления не предоставляет принудительную перезапись.

Интерфейс управления отклоняет пути через символические ссылки, пути за пределами каталога навыков и неоднозначные имена Windows. Это не меняет существующую способность агента загружать связанные навыки.

## HTTP API

`POST /api/ai/agent/manageSkills` использует стандартную структуру ответа API, требует аутентификации вызывающей стороны, прав администратора и отсутствия режима только для чтения в рабочей области. Запрос содержит `action`, а также в зависимости от операции `path`, `target`, `content` и `revision`. Пути используют `/` в качестве разделителя и задаются относительно `data/storage/ai/agent/skills`.

| Операция | Поведение |
| --- | --- |
| `list` | Возвращает дерево файлов через `entries`, где каждый элемент содержит `path`, `isDir` и `editable` |
| `read` | Возвращает `revision` элемента, а для редактируемых текстовых файлов дополнительно исходное `content`; если содержимое не поддерживает редактирование, `content` опускается, а через `readOnlyReason` возвращается `binary`, `encoding` или `tooLarge` |
| `create` | Создаёт новый каталог навыка верхнего уровня и его `SKILL.md` |
| `mkdir` | Создаёт новую папку внутри навыка |
| `write` | Записывает текстовый файл UTF-8 внутри навыка; для существующего файла необходимо передать текущий `revision`, для нового файла используется пустой номер ревизии |
| `move` | Переименовывает элемент в `target` в пределах того же родительского каталога с передачей текущего `revision` |
| `remove` | Удаляет элемент с передачей текущего `revision` |

Файл `SKILL.md` в корневом каталоге, неподдерживаемое содержимое, символические ссылки и удаление папок подчиняются указанным выше ограничениям. При чтении и изменении содержимое проверяется повторно без опоры на снимок `editable` из списка. При несовпадении номера ревизии или недопустимой операции возвращается ошибка без изменения целевого элемента. Существующие API навыков, работающие по имени, сохраняют совместимость; клиенты управления должны использовать этот интерфейс с относительными путями.
