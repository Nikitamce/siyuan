# Закреплённая область панели документов

[English](PINNED-DOCUMENTS.md)

Связанная задача: https://github.com/siyuan-note/siyuan/issues/19401

## Область функциональности

Закреплённая область расположена в верхней части панели документов и отображает реальные дочерние документы, используя закреплённые документы в качестве корней. Порядок корневых элементов не зависит от иерархии документов и сортировки исходных документов; развёрнутые дочерние документы напрямую используют данные исходных документов. Настольная и мобильная версии используют общую реализацию закреплённой области; область можно сворачивать, она ограничена по максимальной высоте и имеет независимую внутреннюю прокрутку.

## Взаимодействие с пользователем

И настольная, и мобильная версии отображают закреплённую область при наличии закреплённых документов и автоматически скрывают её при их отсутствии. Первое закрепление создаётся через меню документа, а после появления области элементы можно добавлять и перетаскиванием. После открепления последнего элемента область автоматически скрывается; список закреплённых документов, полученный при синхронизации, обновляет видимость по тем же правилам. Отдельного переключателя видимости нет, а ранее сохранённая старая конфигурация видимости больше не влияет на эту область. Сворачивание области сохраняет закреплённые документы и их порядок.

| Действие | Поведение |
|---|---|
| Закрепить через меню | Новый элемент помещается в самый верх; для уже закреплённого документа тот же пункт меню переключается на «Открепить» |
| Множественный выбор документов | Одновременно предлагаются «Закрепить» и «Открепить» без различения текущего состояния; при наличии документов из зашифрованного блокнота закрепление не предлагается |
| Меню «Ещё» блокнота | При включённом документе верхнего уровня блокнота для обычных блокнотов доступно закрепление или открепление; после разворачивания закреплённого элемента отображаются видимые документы верхнего уровня этого блокнота |
| Правый щелчок или «Ещё» на закреплённом документе | Открывает меню документа с поддержкой открепления, переименования и других операций |
| Щелчок по значку документа | На рабочем столе открывает выбор значка или следует настроенному поведению разворачивания по значку; на мобильных устройствах разворачивает или открывает документ |
| Перетаскивание на линию вставки корневого уровня | Создаёт или упорядочивает закреплённый элемент; положение исходного документа не меняется |
| Перетаскивание на линию вставки между дочерними документами | Изменяет порядок реальных документов с использованием существующего подтверждения конфликта сортировки |
| Перетаскивание в середину строки документа | Перемещает внутрь реального документа с использованием существующей проверки перемещения |
| Открепить родительский документ | Удаляет только этот корневой элемент; отдельно закреплённые дочерние документы сохраняются |
| Сворачивание панели документов | Одновременно сворачивает закреплённую область и очищает состояние развёрнутости её дочерних документов, сохраняя закреплённые документы и их порядок |
| Переименование или перемещение | Все элементы перечитывают исходный документ; при перемещении между блокнотами обновляется идентификатор блокнота |
| Закрытие обычного блокнота | Сохраняет недоступный элемент и позволяет открепить его; в текущей сессии сохраняется уже прочитанный заголовок, а при невозможности прочитать заголовок отображается ID документа |
| Скрытый документ | Скрывает элемент, но сохраняет запись закрепления и порядок, восстанавливая отображение после снятия скрытия; пока документ скрыт, нельзя добавить новое закрепление, а для открепления в закреплённой области нужно сначала снять скрытие; внутренний маркер скрытия корневого документа блокнота не подпадает под это ограничение; скрытые дочерние документы не учитываются в количестве дочерних документов у стрелки разворачивания |
| Удаление документа или блокнота | Очищает связанные элементы; при чтении списка также отфильтровываются несуществующие исходные документы |
| Зашифрованный блокнот | Действие закрепления не отображается; сервер отклоняет добавление и не возвращает уже имеющиеся аномальные элементы |

Подсказка при перетаскивании на корневом уровне использует линию вставки, а в середине строки — подсветку документа, чётко различая создание элемента и перемещение исходного документа. Проверка перемещения в самого себя или в потомка выполняется существующим интерфейсом перемещения документов. Список дочерних документов загружается в соответствии с действующей сортировкой исходного документа; операция закрепления не записывает в `sort.json` и не меняет наследование сортировки.

## Данные и хранение

`data/storage/pinned-docs.json` использует формат версии 1: `{"version":1,"docs":[{"id":"ID документа","notebook":"ID блокнота"}]}`. Порядок массива является порядком корневого уровня; хранятся только идентификаторы без кэширования содержимого документов. Файл участвует в существующих процессах синхронизации данных и снимков и подчиняется правилам игнорирования синхронизации рабочей области; панель дерева документов обновляется, даже если при синхронизации изменился только этот файл. Одновременное редактирование на разных устройствах использует существующий механизм разрешения конфликтов синхронизации файлов.

Обновления внутри одного ядра сериализуются мьютексом, а интерфейс принимает операции относительного позиционирования, чтобы отправка клиентом всего старого списка не перезаписывала элементы, добавленные другими окнами.

Состояние сворачивания области и развёрнутости поддеревьев сохраняется в хранилище браузера текущего устройства и не записывается в синхронизируемый файл. Один и тот же дочерний документ под разными закреплёнными корнями имеет независимое состояние развёрнутости.

## Реализация и интерфейсы

Оба интерфейса используют POST, требуют аутентификации и роли администратора; интерфейс записи также проверяет режим только для чтения. При успехе `code` равен `0`, при бизнес-ошибке или ошибке параметров — `-1`. Контракты типов находятся в `kernel/apicontract/`, а сгенерированные объявления синхронизируются с репозиторием объявлений плагинов.

| Интерфейс | Запрос | Данные при успехе |
|---|---|---|
| `/api/filetree/getPinnedDocs` | Тело запроса не требуется | Массив, каждый элемент содержит `id`, `notebook`, `name`, `path`, `icon`, `subFileCount`, `unavailable`, `childrenSortMode` |
| `/api/filetree/updatePinnedDocs` | `ids: string[]`, `action: "pin" или "unpin"`, опционально `targetID: string`, `after: boolean` | `null` |

Если цель не указана, операция закрепления помещает элемент в самый верх; если цель указана, элемент вставляется перед ней, а при `after: true` — после неё. Открепление игнорирует параметры позиции. Пакетный запрос сначала проверяет все исходные документы и при ошибке не записывает частичный результат. Поддерево закреплённой области продолжает управляться через существующие интерфейсы списка, перемещения и сортировки документов без создания копий документов.

## Совместимость и восстановление

Неизвестная версия, ошибочная структура или повреждённый файл возвращают ошибку с сохранением исходного файла. Существующие форматы документов, шифрования, истории и резервного копирования не изменяются.

## Область проверки

Регрессия охватывает дедупликацию и порядок элементов, неизменность исходной сортировки, отсутствие частичных обновлений при некорректном пакетном запросе, сохранение данных при неизвестной версии и повреждении, сохранение элементов закрытого блокнота, отклонение и фильтрацию зашифрованных блокнотов, поддержание ссылок, включение в путь синхронизации, разделение перетаскивания на корневом уровне и в поддереве, каталог меню и миграцию порядка из старой конфигурации. Тесты интерфейсов используют реальные функции-обработчики для проверки контракта ответа, а также выполняют существующие тесты совместимости интерфейсов и покрытия маршрутов.
